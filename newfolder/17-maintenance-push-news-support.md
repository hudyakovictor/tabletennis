# Техработы, пуши, новости и техподдержка

## Режим техработ

Из админки можно включить режим техработ.

### Что делает

- Блокирует вход в матч.
- Показывает игроку баннер «Идут технические работы».
- Опционально: показывает ETA.
- Не блокирует просмотр меню, профиля, новостей.

### Как работает

- Флаг в БД или в конфиге: `maintenance_mode: on/off`.
- Клиент при старте и перед матчем проверяет флаг.
- Если `on` — показывает баннер и блокирует matchmaking.
- Если `off` — всё работает как обычно.

### Управление из админки

- Кнопка «Включить техработы» / «Выключить».
- Поле для текста баннера.
- Поле для ETA (опционально).
- Лог: кто, когда, включил/выключил.

## Пуши игрокам

Из админки можно отправлять push-уведомления.

### Типы

- Техработы начались/закончились.
- Новая версия доступна.
- Ивент начался.
- Персональное сообщение (по сегменту).

### Каналы

- Telegram-бот (для Mini App).
- Web Push (для браузерной версии, если поддерживается).
- In-app баннер (всегда).

### Управление из админки

- Выбрать сегмент: все, по региону, по когорте, по платформе.
- Написать текст.
- Выбрать канал.
- Отправить сейчас или запланировать.
- Лог: кто, когда, кому, что отправил.

## Раздел «Новости» в клиенте

В клиенте есть раздел «Новости».

### Что там публикуется

- Обновления версий (patch notes).
- Известные проблемы (known issues).
- Анонсы ивентов.
- Важные объявления.

### Как работает

- Админка → раздел «Новости» → создать пост.
- Пост имеет: заголовок, текст, дату, тег (update/issue/event/announcement).
- Клиент при старте запрашивает список новостей.
- Новые посты помечаются как «новое» до первого открытия.

### Управление из админки

- Создать/редактировать/удалить пост.
- Публикация сразу или по расписанию.
- Привязка к версии игры (опционально).

## Техподдержка в клиенте

В клиенте есть раздел «Поддержка».

### Минимальная версия (MVP)

- Форма обратной связи: тема, текст, скриншот (опционально).
- Отправка в админку как тикет.
- Статус тикета: новый, в работе, решён.
- Игрок видит статус своих тикетов.

### Как работает

- Игрок заполняет форму.
- Клиент отправляет POST в `/api/support/tickets`.
- Тикет сохраняется в БД со статусом `new`.
- В админке появляется в очереди «Поддержка».
- Владелец меняет статус и/или отвечает.
- Ответ приходит игроку в раздел «Поддержка» → «Мои обращения».

### Поля тикета

- ID.
- Player ID.
- Тема.
- Текст.
- Скриншот (опционально).
- Статус.
- Создан.
- Обновлён.
- Ответ поддержки (опционально).

### Управление из админки

- Очередь тикетов с фильтром по статусу.
- Просмотр тикета с историей.
- Смена статуса.
- Ответ игроку.
- Привязка к известной проблеме (опционально).

## Связь с observability

- Если всплеск тикетов по одной теме — это сигнал в Ops.
- Если тикеты совпадают с известной проблемой — авто-привязка.
- Если тикет критичный — эскалация в Telegram-бот.

# Снижение пинга в Telegram Mini Apps

## Специфика Telegram Mini Apps

Mini App — это WebView внутри Telegram. Сетевой стек тот же, что у браузера, но есть ограничения.

- Нет прямого доступа к UDP/WebRTC в большинстве случаев.
- Mini App работает через HTTPS/WSS.
- Telegram может проксировать часть трафика через свои серверы.
- При сворачивании Mini App соединение может рваться.
- Разные версии Telegram WebApp API на разных устройствах.

## Что реально снижает пинг

### WebSocket с keep-alive

WebSocket — основной вариант для realtime в Mini App.

- Одно долгоживущее соединение.
- Ping/pong каждые 20–30 секунд.
- Автоматический reconnect с экспоненциальной задержкой.
- Heartbeat от клиента.

### Бинарный протокол

JSON медленный и тяжёлый.

- MessagePack или Protobuf.
- Delta compression — только изменения.
- Меньше трафика, быстрее парсинг.

### Предзагрузка и кэширование

- Кэшировать статику в IndexedDB или Cache API.
- Предзагружать ассеты до начала матча.
- Service Worker для офлайн-кэша статики.

### Оптимизация под устройство

Telegram даёт информацию о производительности устройства.

- На слабых устройствах меньше частиц и проще шейдеры.
- Физика — всегда фиксированный tick rate.
- Визуал может упрощаться, физика — нет.

### Географический роутинг

- Определять регион по IP на бэкенде.
- Отдавать игроку URL ближайшего WebSocket-сервера.
- Кэшировать выбор в localStorage.

## Ограничения Telegram

| Ограничение | Что делать |
|---|---|
| Telegram проксирует трафик | Учитывать в бюджете пинга |
| WebView на слабых Android тормозит | Оптимизация рендера |
| Соединение рвётся при сворачивании | Reconnect + восстановление состояния |
| Нет UDP | WebSocket + rollback + интерполяция |
| Разные версии WebApp API | Fallback-логика по версии |

## Бюджет пинга

| Этап | Задержка |
|---|---|
| Клиент → Telegram прокси | 5–20 мс |
| Telegram прокси → сервер | 10–50 мс |
| Сервер → обработка | 1–5 мс |
| Обратно | симметрично |
| Итого RTT | 30–150 мс |

Стабильных <50 мс в Mini App добиться сложно из-за прокси Telegram.

Rollback + интерполяция + предсказание обязательны.

## Неткод для скрытия пинга

### Клиентская предсказательность

Игрок видит результат свайпа мгновенно.

Сервер потом подтверждает или корректирует.

### Серверная реконсиляция

Сервер — авторитет.

Проверяет ввод, пересчитывает состояние, мягко поправляет при расхождении.

### Интерполяция чужих движений

Позицию соперника рисуем плавно между двумя последними пакетами.

Скрывает джиттер и рваные пакеты.

### Rollback netcode

Локально симулируем вперёд, предполагая, что соперник продолжает предыдущее действие.

Если прогноз не совпал — откат и пересчёт.

Даёт ощущение офлайн-отзывчивости даже при пинге 80–120 мс.

### Фиксированный шаг физики

Физика идёт с фиксированным tick rate, например 60 Гц.

Независимо от FPS устройства.

Иначе симуляция разойдётся и rollback сломается.

### Компрессия и приоритизация

- Отправлять только изменения.
- Бинарные форматы вместо JSON.
- Критичные данные каждый тик.
- Косметика реже.
- Несколько флагов в один байт.

### UDP вместо TCP

TCP при потере пакета ждёт повторную передачу.

Для realtime лучше UDP с собственной логикой надёжности.

Если WebSocket (TCP) — компромисс для старта.

Позже можно перейти на WebRTC DataChannel (UDP).

## Региональные серверы

### Пороги пинга

| Пинг | Ощущение | Действие |
|---|---|---|
| < 35 мс | Отлично | Ничего не надо |
| 35–65 мс | Хорошо | Норма |
| 65–100 мс | Заметно, но играбельно | Rollback + интерполяция |
| 100–150 мс | Плохо | Нужен ближайший сервер |
| > 150 мс | Неприемлемо для PvP | Обязательно региональный сервер |

### Архитектура мультирегиона

```text
[Игрок]
   |
   v
[Гео-DNS / Anycast]
   |
   v
[Региональный game server]
   |
   +--> [Локальная БД телеметрии]
   +--> [Локальный matchmaking]
   |
   v
[Глобальный сервис]
```

- Гео-DNS или Anycast направляет к ближайшему серверу.
- Matchmaking в каждом регионе свой.
- Телеметрия пишется локально, агрегаты — в глобальный слой.

### Что заложить в код сразу

- Поле `region` в сессии и matchmaking.
- Конфиг `REGION_ENDPOINTS`.
- Пинг-зонд при старте.
- Пороговое предупреждение при пинге > 100 мс.
- Session affinity при реконнекте.
- Абстракция транспорта.

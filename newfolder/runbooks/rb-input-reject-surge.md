# Runbook: `rb-input-reject-surge` — Всплеск отказов ввода (`OUTSIDE_ZONE`, `WRONG_DIRECTION`, `STATIC_CLICK`)

## Триггер
Доля отклонённых нажатий (`reject_code IS NOT NULL`) в зоне `Ops` выросла более чем на `2σ` от суточной нормы (например, `> 32%` по сегменту Touch/Android после релиза).

## Симптомы
- Жалобы игроков в тикетах: «ракетка не отбивает быстрые подачи», «свайп не засчитывается».
- Зона `Balance` фиксирует смещение 90-го перцентиля `along` или `across` за пределы текущего овала `MATCH_RULES`.

## Пошаговая диагностика
1. Открыть вкладку **Зона Balance** → включить фильтр `touch` и проверить **2D-теплокарту овала нажатий**.
2. Сравнить `rules_version` и активный A/B-вариант в **Зоне Lab** (не раскатился ли багованный тестовый `sig`).
3. Проверить блок рекомендаций p90 (`ovalForwardPx`, `ovalBackPx`, `ovalSideTouchPx`).

## Команды для диагностики и отката
```bash
# Прогнать эталонный симулятор шума и калибровку 144 траекторий
cd ../source/game && npm run calibrate && npm run noise
```
- Если причина в неудачном A/B-тесте — остановить эксперимент в **Зоне Lab**.
- Если после обновления камеры изменился экранный масштаб — создать/подтвердить **Решение HITL (`update_match_rules`)** для возврата на предыдущую стабильную ревизию `MATCH_RULES`.

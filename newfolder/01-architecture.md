# Архитектура админ-панели

## Общая схема

```text
[Игра TOPSPIN ARENA]
        |
        v
[Игровой бэкенд]
        |
        +--> [Хранилище телеметрии]
        +--> [Хранилище маркетинговых событий]
        +--> [Хранилище логов ввода]
        |
        v
[Админ-панель]
        |
        +--> [Зона Ops]
        +--> [Зона Fraud]
        +--> [Зона Balance]
        +--> [Зона Market]
        +--> [Зона Lab]
        |
        v
[Директор — сводки и чат]
```

## Принципы

1. Игра не знает об ИИ.
2. ИИ работает только на бэкенде.
3. Игрок не видит упоминаний ИИ в интерфейсе.
4. Клиент не содержит API-ключей.
5. Клиент не обращается к провайдерам ИИ напрямую.
6. Каждая зона изолирована от других зон.
7. Директор не имеет доступа к сырым логам.
8. Все значимые действия требуют подтверждения человека.

## Пять зон

| Зона | Назначение | Приоритет |
|---|---|---|
| Ops | Нагрузка, FPS, краши, аномалии ввода | Высокий, realtime |
| Fraud | Подозрения на ботов, мультиаккаунты, платёжный фрод | Высокий, near-realtime |
| Balance | Баланс сложности, ввода, MATCH_RULES | Средний, daily |
| Market | Когорты, LTV, ROAS, каналы трафика | Средний, daily |
| Lab | Гипотезы, A/B, разбор тестов | Низкий, batch |

## Изоляция зон

Каждая зона имеет:

- собственный API-ключ провайдера ИИ;
- собственную схему в БД;
- собственную историю общения с директором;
- собственный набор шаблонов промптов;
- собственные лимиты запросов и токенов.

Зона не видит:

- чат владельца с директором;
- сводки других зон;
- сырые логи других зон;
- промпты других зон;
- API-ключи других зон.

## Данные

На старте все данные хранятся в одной БД в РФ.

Схемы уже разделены:

- `ops`;
- `fraud`;
- `balance`;
- `market`;
- `lab`;
- `director`;
- `players`;
- `payments`.

В каждой таблице с персональными данными есть поле `region`.

Это позволит позже разделить данные по регионам без полной переделки.

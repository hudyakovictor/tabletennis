# Протокол описания багов и недоработок (реестр 150+ пунктов, 25 категорий)

**Проект:** TOPSPIN ARENA  
**Версия:** 1.0  
**Статус:** обязателен. Каждый пункт в реестре — одна заполненная карточка по TEMPLATE-BUG.md.

---

## 1. Назначение

В игре зафиксировано более 150 пунктов разного уровня — от блокеров релиза до косметических шероховатостей. Они распределяются по **25 факторам и категориям**. Без единого протокола описания реестр превращается в свалку: дубликаты, невоспроизидимые пункты, потерянные владельцы, неясные критерии закрытия.

Этот протокол делает реестр управляемым:
- каждая карточка описывается одинаковыми полями;
- каждая карточка принадлежит одной из 25 категорий;
- приоритет и критичность ставятся по одной матрице;
- пункт переходит в работу только после прохождения цикла PROTOCOL-EXPERTS.ru.md (6 фаз → консенсус).

| **Приоритет** | P0 … P3 (раздел 4) | Да | P1 |
| **Критичность** | Блокер / Мажор / Минор / Косметика | Да | Мажор |
| **Сложность** | S / M / L (оценка команды) | Нет (ставится на совещании) | M |
| **Владелец** | Код эксперта, ответственный за решение | Нет (ставится на совещании) | GD-1 |
| **Статус** | Открыт / В обсуждении / Решение принято / В работе / На тесте / Закрыт / Отложен / Отклонён | Да | Открыт |

**Правило:** карточка без шагов репродукции не может иметь приоритет выше P2.

## 4. Матрица приоритетов и критичности

| | Блокер | Мажор | Минор | Косметика |
|---|--------|-------|-------|-----------|
| **P0** — blokcer релиза | Исправляем до релиза, без обсуждения alternatives | P0 | P1 | P2 |
| **P1** — следующий спринт | P0 | P1 | P2 | P3 |
| **P2** — при ресурсах | P1 | P2 | P3 | Отложен |
| **P3** — бэклог/вдохновение | P2 | P3 | Отложен | Архив |

- **P0** = без Fix не выходит сборка (звук сквозной, प्रदर्शन на реальных устройствах, сохранения, FTUE-финалка и т.д. из дорожной карты).
- Пункт без репродукции не старше P2.
- Категория CT-16 (онлайн) вне скоупа 1.0 — пункты помечаются «вне скоупа» и не блокируют релиз.

## 5. Правила попадания в реестр и закрытия

1. **В реестр попадает только заполненная карточка** (раздел 2) с источником и шагами репродукции.
2. **Один пункт = одна карточка.** Дубликаты закрываются со ссылкой на оригинал.
3. **Закрытие только после прохождения цикла совещания** (6 фаз → консенсус) и прохождения теста/регресса.
4. **Владелец меняется только на совещании** (фаза F) — проставляется код эксперта.
5. **Реестр пересматривается каждую неделю:** пункты без активности 30 дней → статус «требует репродукции»; без репродукции 60 дней → архив с причиной.
6. **Никаких подсказок:** приоритет и критичность ставятся командой на данных, а не по указанию извне.

## 7. Связь с протоколом обсуждений

Каждый пункт из этого реестра входит в совещание по `PROTOCOL-EXPERTS.ru.md` через фазы A–F. Итог совещания (код решения, владелец, критерии приёмки, статус) заносится обратно в строку реестра. Пункт считается «закрытым по протоколу» только если в строке есть ссылка на протокол совещания и пройден тест/регресс.

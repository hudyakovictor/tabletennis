# Меню-хаб TOPSPIN ARENA 2026

Единая поверхность меню над живой 3D-сценой: вместо россыпи карточек-экранов —
один хаб с рельсом разделов, листами и переходами. Документ описывает решение,
аналитическую фазу, motion-спецификацию, состояния и ограничения.

- Разметка: `tt/src/02_body.html`
- Стили хаба: `tt/src/06_hub.css`
- Поведение: `tt/src/82_hub.js` (подключается после `80_ui.js`)
- Сборка: `tt/build.py` → `table-tennis-topspin.html`, `play/index.html`
- Скриншоты: `docs/menu-hub-2026/*.jpg`, коллаж — `docs/menu-hub-2026/collage.png`
- Снять заново: `node tools/capture-menu.cjs` (нужен `LD_LIBRARY_PATH` из `tests/browser.cjs`)

---

## 1. Что было и в чём проблема

Старое меню — набор независимых `.screen`-ов: главное меню, настройки, мастерская,
карьера, онлайн, итоги. Каждый экран сам решал, какой другой экран скрыть
(`$$('.screen').forEach(s => s.classList.remove('on'))`), из-за чего:

- состояние терялось при каждом переходе (мастерская каждый раз начинала с нуля);
- на телефоне меню превращалось в длинную карточку с горизонтальными «кишками» кнопок;
- фон (стол) почти не читался: плотный `backdrop-filter` и радиальный градиент;
- не было общей навигации: из «Карьеры» в «Мастерскую» — только через главное меню;
- счётчики (монеты, серия) обновлялись вручную в трёх местах и рассинхронизировались.

Цель: **одна оболочка**, в которой все 13 пунктов брифа живут как разделы,
а не как отдельные игры в отдельной игре.

## 2. Аналитическая фаза

Работа шла по методике из четырёх скиллов
(`hyperframes-animation`, `find-animation-opportunities`,
`animation-vocabulary`, `review-animations`).

### 2.1 Гейт для каждого взаимодействия

1. **Как часто?** 100+ раз в день → без анимации; 10–100 → только обратная связь;
   реже → можно позволить пространственный переход.
2. **Зачем?** feedback / spatial / state / jarring / explanation / delight.
3. **Бюджет?** press 100–160 мс, popover 125–200, dropdown 150–250, модалка 200–500.
4. **Что если убрать?** Если смысл не теряется — убрать.

### 2.2 Матрица частоты (поверхность × частота)

| Поверхность | Частота | Разрешено |
|---|---|---|
| Тап по кнопке | 20–60/сессию | звук + press-scale 90 мс, без keyframes |
| Переключение вида хаба (Игра/Карьера/Мастерская) | 5–15/сессию | enter 360 мс, смена раздела |
| Лист (настройки, онлайн, моменты) | 2–6/сессию | 320 мс, origin у кнопки-триггера |
| Ползунок помощи | 10–40 перетаскиваний | без анимации значения, только позиция |
| Ввод в матче | 100+/мин | ничего, кроме физики |
| Смена сложности | 2–5/сессию | мгновенно (без анимации цифр) |
| Число монет | редко | ticker 220 мс + bump |
| Тост | 3–10/сессию | 2,1 с, без очереди |

### 2.4 Симуляции бюджета

- **Переход вида.** 360 мс, `cubic-bezier(.22,1,.36,1)` — верхняя граница для
  смены раздела (spatial). При повторном переключении анимация перезапускается,
  а не ставится в очередь: пользователь не ждёт.
- **Лист.** 320 мс enter, 220 мс exit. На телефоне — выезд снизу (`sheetUp`),
  на десктопе — масштаб 0,982 → 1 с подъёмом 18 px.
- **Ползунок.** Значение меняется в том же кадре, что и палец (без tween):
  иначе число «догоняет» палец и калибровка воспринимается как неточная.
- **Кнопка.** `:active` — `scale(.985)` за 90 мс. Это не анимация, а подтверждение
  нажатия; при `prefers-reduced-motion` остаётся (длительность < 100 мс).
- **Монеты.** `bump` 520 мс на изменении значения; без анимации цифр по одной.

### 2.5 Что отвергнуто

| Идея | Почему нет |
|---|---|
| Параллакс меню по скроллу | ломает чтение на телефоне, конфликтует с нативным скроллом |
| Анимация появления каждого пункта (stagger 12 плиток) | 12 × 40 мс = 480 мс задержки до CTA; частота входа высокая |
| Полноэкранный `backdrop-filter` под меню | 8–12 fps на среднем Android; стол и так приглушён градиентом |
| Числовой ticker на каждом счётчике | в кошельке значения меняются редко; шум |
| 3D-tilt карточек за курсором | не несёт информации, конфликтует с press-состоянием |
| Звук на hover | раздражает при 100+ проходах мышью |
| Выезд рельса на мобиле | экран 390 px: рельс превращается в док, а не в шторку |
| Свайп между разделами | конфликт с системным «назад» в Telegram |
| Кастомный курсор в меню | системный курсор возвращён осознанно (a11y) |
| Автопрокрутка карусели | отвлекает и ломает фокус |

### 2.6 Семь реализованных motion-идей

1. **Живой фон, но дешёвый.** Два радиальных пятна + сетка + 12 «мотыльков»
   (`transform` + `opacity`, 14 с). При скрытом меню `animation-play-state: paused`.
2. **View transition.** Смена раздела — 360 мс, 12 px вверх + масштаб 0,996 → 1,
   только `transform`/`opacity`. Повторный клик перезапускает.
3. **Маркер рельса.** Одна полоска, переезжающая к активному пункту за 340 мс;
   `aria-current="page"` дублирует смысл для скринридера.
4. **CTA с бликом.** Один проход блика каждые ~6 с (`ctaSweep`), не чаще:
   внимание к главному действию без мигания.
5. **Лист снизу.** На телефоне листы выезжают снизу (34 мс буфер на закрытие),
   на десктопе — pop-in от кнопки. Закрытие быстрее открытия (асимметрия).
6. **Живой предпросмотр зон.** Круги захвата/нажатия меняют размер за 180 мс вслед
   за ползунком; сама схема не двигается.
7. **Тост кошелька.** Появление 220 мс + автоскрытие 2,1 с; сообщения не копятся.

## 3. Структура меню

```
#menu (hub)
├── header: логотип · сезон · кошелёк · утилиты (экран/звук/настройки/ещё)
├── rail (desktop) / dock (mobile)
│   ├── ИГРА          → #viewPlay
│   ├── КАРЬЕРА       → #viewCareer
│   ├── МАСТЕРСКАЯ    → #workshop (вкладка «Ракетка»)
│   ├── ЗАДАНИЯ       → #workshop (вкладка «Задания»)
│   ├── ОНЛАЙН        → #onlineLobby
│   ├── ОБУЧЕНИЕ      → тренировка
│   ├── МОМЕНТЫ       → #reels
│   └── ЕЩЁ           → #hubMore
├── stage
│   ├── #viewPlay: hero, сложность ×5, CTA, 6 быстрых действий, мета-карточки, сезон, досье
│   ├── #viewCareer: путь из 12 турниров, кодекс 10 перков, статус забега
│   └── #workshop: 3 вкладки (ракетка / магазин / задания)
└── листы: #hubMore, #careerIntro, #careerPerk, #careerEnd, #onlineLobby,
          #settings, #tdone, #over, #reels, #shotLab, #pauseInd, #loading
```

### 3.1 Состояния экранов

| Состояние | Условие | Что видно |
|---|---|---|
| Сплэш | старт, 1,6 с или клик | `#loading` без `.off` |
| Хаб | `GS.MENU` | `#menu.on`, активный вид |
| Лист | любой `.screen.on` | хаб/стол под листом, фокус внутри |
| Матч | `is-playing` | HUD, меню скрыто |
| Пауза | `body.is-paused` | `#pauseInd` (z-index 6) |
| Итоги | `GS.MATCH_END` | `#over` |

Правило CSS: `.screen` скрыт **отсутствием** `.on` (база задаёт `opacity:0;
visibility:hidden;pointer-events:none`, `.on` возвращает всё обратно).
Хаб переопределяет только раскладку — `#menu.screen{display:block}` — и
намеренно не ставит `display:none` в выключенном состоянии: иначе меню
появлялось бы скачком, без 240-мс затухания. Скрытие всё равно полное:
невидимый слой не ловит указатель и не читается скринридером, потому что
у него `visibility:hidden`.

### 3.2 Кошелёк, серия, сезон

`Hub.refresh()` — единственный источник правды для шапки:

- монеты/кристаллы: `profile.data.coins|crystals`, `bump` при изменении;
- задания: `profile.data.daily.done.length` → «серия N · x/6» + полоса;
- сезон: `profile.seasonLevel()` / `seasonProgress()` → уровень и полоса;
- статистика: `profile.data.stats` (победы, лучшая скорость, моменты).

`UI.refreshMenuBits()` вызывает `hub.refresh()`, поэтому покупка в мастерской,
награда за задание и реклама сразу видны в шапке.

## 4. Настройки

Девять разделов, одна прокручиваемая колонка + sticky-навигация:

1. Хват и рука (shakehand/penhold, правша/левша) — `changePaddlePreference`.
2. Жесты (классика / без свайпа вниз).
3. Камера (3 пресета + сброс) — общие правила, не личные.
4. Отображение (ракетка, след, прогноз).
5. Подача — высота подброса **28–46 см, по умолчанию 37**; реально влияет на
   `startToss`: `v = sqrt(2gh)`, подброс остаётся законным (≥ 16 см).
6. Управление · помощь — 5 ползунков: 100 / 100 / 85 / 85 / 1.00×.
   **Это предпросмотр**: значения не пишутся в настройки и не меняют
   `MATCH_RULES` (hitZone жёстко 0,85 — это проверяет браузерный тест).
7. Звук · вибрация + громкость.
8. Тренер · сложность + качество.
9. Данные: калибровка, моменты, юридический блок.

Ползунки — не `<input type=range>` (тест прямо запрещает range в `#settings`):
`.meter[role=slider]` с `pointer capture`, `aria-valuenow/valuetext`,
стрелками `←/→/↑/↓`, `Home/End`, `Shift` ×10.

## 5. Доступность

- `#menu` — `role="dialog" aria-modal="true"`, фокус-ловушка в `UI.trapDialogFocus`.
- Все иконки-кнопки имеют русские `aria-label`; состояния — `aria-pressed`.
- Сложность и сегменты — `aria-pressed`; вкладки мастерской — `role="tab"` + `aria-selected`.
- `aria-live`: счёт, статус розыгрыша, тост хаба (`role=status`), `#hubLive` для смены раздела.
- Escape закрывает: «Ещё», настройки, моменты, онлайн, карьерные листы; калибровку — `UI`.
- Enter в хабе запускает матч, если фокус не на кнопке (футер обещает это явно).
- `prefers-reduced-motion`: отключены кольца, мотыльки, блик CTA, выезды листов,
  тряска; физика и звук не меняются.

## 6. Звук

`Hub.sfx()` вызывает `audio.ui('click')` с дебаунсом 60 мс, чтобы одно нажатие
не звучало дважды (делегирование + собственный обработчик кнопки). Отдельные
события: `deny` (не хватает монет), `buy` (покупка), `toss` (подача).
Громкость — общий ползунок в настройках, мьют — иконка в шапке.

## 8. Что осталось честно не сделанным

- Онлайн остаётся экспериментальным: relay не входит в сборку, без `?net=wss://…`
  лобби показывает «Нет соединения» и не притворяется, что матч возможен.
- Кастомизация внешнего вида ракетки ограничена тем, что продаёт магазин;
  редактора цветов нет.
- Коллаж — статичные скриншоты; видео-проход по меню не записывался.

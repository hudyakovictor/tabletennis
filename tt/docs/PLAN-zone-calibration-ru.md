# План: покрытие 15×15, калибровка и отладка

## 1. Что измерено (стенды уже в репозитории)

`tt/tools/zone_matrix.js` — 10 ударов × 3 мощности + 4 подачи × 2 мощности × 225 клеток. Каждая клетка проходит боевой конвейер: `deriveStroke → refineRacket (assist 1.0, quality 0.9) → impactRacket → predict` на production-шаге. `tt/tools/reach_envelope.js` — съём «свидетелей»: 3000 квазислучайных точек (Холтон) по сырым параметрам удара `(dE, dA, scale, damp)` без всякого солвера, с проверкой победителей на точном шаге. Свидетели показывают, что физика **может**, а солвер — что он **делает**. Это и есть главное различие: без него любая дырка выглядит как «физика не позволяет».

Во время замеров нашлась ошибка легальности: подача за линией (до 33 из 225 запросов) считалась легальной — проверялась только сторона площадки. Исправлено сразу (ITTF 2.06.4: второй отскок обязан быть в столе), иначе колонка «легально» врёт и мерить нечего. Гейты после правки: 144/144 unit, 169/169 browser.

## 2. Результаты

Подачи — попадание в запрошенную клетку из 225 (солвер) против свидетелей:

| подача | x0.7 | x1.15 | свидетели x0.7 / x1.15 |
|---|---|---|---|
| TOP | 12 | 8 | 165 / 122 |
| BACK | 13 | 2 | 156 / 118 |
| SIDE | 12 | 12 | 162 / 111 |
| FAST | 7 | 3 | 129 / 98 |

Систематический снос по глубине `meanDz = −0.24…−0.35 м` (всегда глубже, чем просили), `meanErr 0.29…0.82`. Ряд `iz=14` (0–9 см от сетки) недостижим физически (0–7 клеток), но `iz=8…13` (0.09–0.55 м) — достижим: например, для TOP×1.15 клетка `iz=12` берётся параметрами `dE=−0.196, dA=0.013, sc=0.367, dmp=0.58` с ошибкой 0.021 м. То есть короткая подача возможна, а солвер её не выдаёт.

Возвраты (мощность 1.0): свидетели против попаданий — DRIVE 99/78, FLICK 126/92, PUSH **107/10**, CHOP **92/25**, LOB **79/6**, BLOCK 115/3, COUNTER 48/37, SMASH 52/127, LOOP 44/121, DROP 0/0. Там, где солвер обгоняет свидетелей (LOOP, SMASH), оценка занижена выборкой, поэтому дефицит считаем только по строкам, где свидетелей заведомо больше. Карта: глубокая зона (iz 0–5) покрыта, ближняя (iz 9–14) — нет; на возвратах она даёт `n` (сетка), `o` (за линию) и даже `s` (своя половина, LOB: 16 клеток).

## 3. Три диагноза (код + цифры)

**A. Подачи: штраф за «мёртвую» подачу сильнее цели в 5 раз.** В `solveServeStroke().score()` цена = `|b2 − aim|` плюс `dead = (0.70 − |b2.z|) · 5.0`. Для короткой цели любой законный «глубокий» вариант выигрывает: при `aim z=−0.23` идеальная короткая подача стоит 2.35 штрафа, а промах на 0.6 м в глубину — 0.6. Солвер рационально уходит в глубину; отсюда и `meanDz −0.3`, и 2–13 попаданий. Второй вклад: спуск по координатам без мульти-старта и без критерия «попал в клетку» — он останавливается на первой законной подаче.

**B. Возвраты: ассист не признаёт недостижимость.** Для DRIVE (прилёт 8.5 м/с) `solveLaunch().err` растёт монотонно при приближении цели к сетке: 0.058 (z=−1.32) → 0.348 (−0.96) → 0.531 (−0.78) → 0.714 (−0.59), а мяч после этого стабильно ложится в z≈−0.80. Код видит `err`, но использует его только как «смягчить кисть один раз», а в `target` возвращает по-прежнему недостижимую точку. Итог: игрок просит коротко — получает длинно, и никакой диагностики этого не видно.

**C. Что не является багом.** BLOCK: ассист намеренно пассивен (`refineRacket` не запускает поиск для блока), поэтому 3/225 — следствие дизайна, а не дефект; лечится атласом и подсказкой, а не солвером. DROP: 0 свидетелей и 225 «своя половина» — шаблон жеста не умеет ронять мяч на чужую половину при этих мощностях. CHOP×1.35: 96 `invalid` — шаблон не воспроизводит удар на такой скорости.

## 4. Идеи отладки и калибровки (реализуемые)

1. **Бот против бота, headless.** Прогон N раундов без рендера, по удару пишется JSONL: тип удара, мощность, `dE/dA/sc/dmp`, цель, факт, `sol.err`, `b2`, легальность, время солвера. Поверх — отчёты: доля попаданий по клеткам, дефицит удара, «кто выигрывает очки и каким ударом» (баланс), p95 времени солвера. Это единственный способ увидеть деградацию на 10⁵ ударах, которую 225 клеток не ловят.
2. **Лог реальной игры + детерминированный реплей.** Кольцевой буфер последних 300 ударов (вход, состояние ракетки, seed), кнопка «сохранить», файл `.jsonl`. Реплей прогоняет запись через текущий код и показывает расхождение «тогда/сейчас» — так баг превращается в тест-кейс за один клик.
3. **Интерактивный тренажёр «попади в клетку».** Сетка 15×15 поверх стола, режимы: 9 целей (3×3), 25, вся сетка; выбор удара; счётчик попаданий и heat map по клеткам; серии «правый угол → левый угол → короткая». Результаты пишутся в тот же JSONL. Это проверяет не физику, а связку «прицел — рука — ассист», включая то, что в коде не видно: где игрок физически не может достать.
4. **След решения (`solveTrace`).** Для одного удара сохранять список кандидатов с их ценой и `why` (back/fast/net/own/long/out/ok) — 20 строк вместо гадания. Включается флагом, в бою выключен.
5. **Монте-Карло по подбросу.** 225 клеток сейчас считаются при фиксированном подбросе (1.14 м, 1.44 м, −0.8 м/с). Нужен разброс высоты ±15 см, положения ±10 см, скорости ±0.4 м/с и фазы: покрытие должно оставаться, иначе калибровка подгонится под один подброс.
6. **Детектор «невозможного возврата».** В бою проверять факт против атласа достижимости для данного прилёта; расхождение — в лог с полным состоянием. Так ловятся «достал то, что достать нельзя» без ручных тестов.
7. **Property-тесты и корпус.** Инварианты на случайных жестах: подача никогда не легальна за пределами стола, второй отскок не на своей половине, возврат не уходит за линию при достижимой цели. Каждый найденный кейс замораживается в JSON и переигрывается `node --test`.

## 5. Правки кода, порядок и приёмка

1. **Подачи (A).** Штраф `dead` взвешивать по цели: вес = 0 для короткой цели, 5.0 — только когда просили глубоко (`clamp((|aim.z| − 0.70)/0.50, 0, 1)`); добавить приёмочный критерий «попал в клетку» и мульти-старт (3 сида: лучший, короткий `sc≈0.37/dmp 0.58`, средний). Приёмка: ≥ 90/225 на каждый тип подачи (≥55% свидетелей), `|meanDz| ≤ 0.08`, 0 нелегальных, солвер ≤ 35 мс.
2. **Возвраты (B).** `sol.err` возвращать как `reachErr`; при `err > 0.12` — бисекция по глубине цели (5 шагов, монотонно) до достижимой точки, спуск вести уже по ней; в кадр вернуть фактическую цель и `clamped: true`. Приёмка: строки 9–14 не дают `o`/`s`; `|meanDz| ≤ 0.10` для достижимых целей; ошибка относительно фактической цели ≤ 0.12 м.
3. **Тёплый старт по клеткам.** Таблица `(dE,dA,sc,dmp)` из `reach_envelope` вшивается в билд как первый кандидат; `score()` её проверяет и, если законна и ближе к цели, оставляет. Приёмка: покрытие подач ≥ 130/225, время не растёт.
4. **BLOCK — атлас, не фикс.** Показывать достижимую зону для текущей ориентации; в матрице считать отдельной строкой «без ассиста».
5. **DROP и CHOP×1.35 — новые шаблоны** (своя половина; 96 `invalid`) — отдельная задача, не смешивать с калибровкой.
6. **Регрессия.** После каждого шага: build, 144 unit, 169 browser, `audit_matrix` 162/0, `audit_rules` 23/23, `audit_match` 0 нарушений, `zone_matrix` «до/после».

## 6. Чего не делаем

Не трогаем косметику сверх сетки тренажёра, не «улучшаем» физику ради цифр, не расширяем коробку ракетки и не поднимаем `SERVE_VMAX`, пока не доказано, что клетка недостижима физически, а не солвером.

# МОДУЛИ — карта исходников TOPSPIN ARENA

Документ для делегирования: что лежит в каждом файле `tt/src/`, от чего зависит,
и какие модули можно переписывать отдельно, а какие — опасно трогать.

---

## 0. Как устроен билд (читать первым)

Игра — **один самодостаточный HTML** без сети и внешних ассетов. Исходники в `tt/src/`
склеиваются в один файл скриптом `tt/build.py`.

- `JS_ORDER` в `build.py` — **единственный источник порядка конкатенации**. Все
  `*.js` из `tt/src/` попадают в бандл в этом порядке, каждый в своей `<script>`
  области видимости верхнего уровня (`'use strict'`, общие глобалы).
- **Инвариант (жёсткий):** каждый файл `*.js` в `tt/src/` обязан быть перечислен
  в `JS_ORDER`. Лишний/забытый файл → `build.py` падает с `SystemExit`. Это
  защита от тихого «WebGL недоступен» на старте. Добавил модуль — внеси в список.
- Порядок = порядок зависимостей: листы (math → physics → gl) идут раньше, чем
  их потребители (scene → game → ui → boot). Переписывать файл можно, не меняя
  его место в `JS_ORDER`, если вы не меняете глобалы, которые он объявляет.
- CSS (`05_style.css`) и разметка (`02_body.html`) инлайнятся в `<head>`/`<body>`.
- Логотип и записанные сэмплы аудио (`sounds/*.wav|mp3`) встраиваются base64.
  Сэмплы — отдельным глобалом `window.__AUDIO_SAMPLES__` (не внутри `50_audio.js`,
  чтобы node-тесты могли грузить аудио-модуль напрямую). Нет папки `sounds/` —
  билд всё равно проходит, звук уходит в рантайм-синтез.

Команды (корень репо, `package.json`):

| команда | что делает |
|---|---|
| `npm run build` | перегенерировать правила + собрать оба бандла (`table-tennis-topspin.html` и `play/index.html`) |
| `python3 tt/build.py <цель>` | собрать только в указанную цель |
| `npm test` | **`node --test tests/*.test.js` — основной гейт, 174 теста** |
| `npm run test:browser` | отдельный Chromium-набор (`tests/browser.cjs`), Linux-флаги, на macOS не стартует — не гейт |
| `npm run relay` | WebSocket-ретранслятор для сетевого режима (`tt/server.js`) |

## 1. Слои архитектуры

```
90_boot ──► инстанцирует всё, вешает на window.__game
   │
80_ui ◄─── 70_game (оркестратор: GS-стейт-машина, правила, vfx)
   │           │
   │      ┌────┴─────────────────────────────────────────────┐
   │      ▼         ▼          ▼        ▼       ▼      ▼      ▼
   │  57_camera  60_scene  40_swipe  55_ai  65_train 58_coach 59_replay
   │      │         │         │        │             
   │      └─────┬───┴────┬────┴───┬─────┘
   ▼            ▼        ▼        ▼
[84_racket→86_meta]  30_physics  38_paddle_motion  12_match_rules
                     │
                    20_gl   50_audio  75_feedback/music  76_emotion  81_uiAnim
                     │            │
                    10_math ◄─────┴── (leaf, общий для всех)
```

Правило чтения: **стрелка `A → B` = «A зависит от B».** Файлы ниже по графу —
стабильные листы, их переписывать по-отдельности рискованно (много потребителей).
Файлы-«листья» справа (audio/music/emotion/uiAnim/telemetry) — почти ни от чего
не зависят, их можно отдавать на переписку спокойно.

## 2. Справочник по файлам

Формат: **назначение · ключевые глобалы · зависит от · риск**.
Риск: 🟢 можно переписывать отдельно · 🟡 связан, править аккуратно · 🔴 ядро, не трогать без координации.

### `10_math.js` — 🔴 ядро (лист)
- **Назначение:** линейная алгебра без лишних аллокаций (vec3/mat3/mat4/quat), шум,rand.
- **Глобалы:** `TAU DEG clamp lerp smoothstep sign rnd rndSym gauss V3 M4 Q hash1 noise1`.
- **Зависит от:** ничего (лист). **Потребители: буквально все.**
- **Можно ли отдать:** менять сигнатуры `V3/M4/Q` нельзя — развалится весь бандл. Разрешены только additive-правки (новая функция, не меняющая существующие).

### `12_match_rules.js` — 🔴 ядро контракта управления
- **Назначение:** единая версионируемая «игроцкая» контрактура: зоны нажатия, захвата, овал `press`-зоны, тайминг бэк-swingа. Дистанции в метрах, размеры маркеров в CSS-px (NOT hit-радиусы).
- **Глобалы:** `MATCH_RULES PRESS_REJECTION_REASONS installUnifiedControls playerCaptureLimits playerInCaptureRange strikeCueModel ballCaptureTarget measureCaptureAllowance pressHitZone(Oval) pressServeZoneOval pressZoneForBall serveTossRise …`
- **Зависит от:** `10_math`. **Потребители:** `40_swipe`, `70_game`, `80_ui` (hit-test/HUD).
- **Можно ли отдать:** `version` в `MATCH_RULES` — согласован с тестами `controls/press-zone`. Правки геометрии зон обязательны с прогоном этих тестов.

### `20_gl.js` — 🔴 ядро рендера
- **Назначение:** самописный WebGL2/1 forward-рендерер: Blinn-Phong+GGX, hemi-IBL, PCF-тени, HDR offscreen, bloom, ACES, виньетка, CA, зерно, speed blur. Плюс билдеры геометрии.
- **Глобалы:** `geoAlloc geoGrow geoPush geoTri geoQuad makeBox makeSphere makeCylinder makePaddleBlade makePlane makeQuad(UV) makeCapsule … class Renderer`.
- **Зависит от:** `10_math`. **Потребители:** `60_scene`, `70_game`.
- **Можно ли отдать:** переписать внутренности шейдеров/пайплайна можно **только если интерфейс `Renderer` (quality, draw-вызовы) сохранён**. Иначе — каскад в scene/game.

### `25_career.js` — 🟡
- **Назначение:** карьерный/турнирный слой: перки, генерация сетки, соперники по ELO.
- **Глобалы:** `PERKS TOURNAMENTS getAvailablePerks pickThreePerks generateOpponent class Career`.
- **Зависит от:** `10_math` (rnd). Потребитель: `70_game`/`86_meta`.
- **Можно ли отдать:** почти автономный. Безопасный кандидат на переписку. Держать контракт `Career` для game/meta.

### `27_network.js` — 🟡
- **Назначение:** сетевой режим (host/guest через relay). Протокол `state`/`input`.
- **Глобалы:** `class NetworkManager`.
- **Зависит от:** `10_math`, модель состояния game. Потребитель: `70_game`, `90_boot`, relay (`tt/server.js`).
- **Можно ли отдать:** изолирован; переписка реальна при неизменности формата сообщений. Тесты `network.test.js`.

### `30_physics.js` — 🔴 ядро физики
- **Назначение:** жёсткая сфера с аэродинамикой и ударами Кулона; все константы ITTF (SI). Координаты: +x вправо, +y вверх, +z к игроку. `solveLaunch/_tryLaunch` — баллистика.
- **Глобалы:** `PH` (константы), шагалки физики, `solveLaunch _tryLaunch`.
- **Зависит от:** `10_math`. **Потребители:** `40_swipe 55_ai 57_camera 58_coach 60_scene 65_train 70_game …` — почти вся игра.
- **Можно ли отдать:** **нельзя менять `PH.*` и сигнатуру `solveLaunch` без координации** — от них зависят hit-test, камера, AI, туториал. Единственный «скучный» случай — правка числа с проверкой `core`/`physics`-тестов.

### `38_paddle_motion.js` — 🟡
- **Назначение:** контракт движения ракетки (только ракетка, без руки). Профили strokes, углы, `PaddleReadClock`.
- **Глобалы:** `PADDLE_PROFILES paddleStrokeFamily paddleGripProfile paddleForehand paddleContactRange wristStrokeKey stepPaddleAngle paddleFaceAngles class PaddleStrokeMotion paddleBottomExtent keepPaddleAboveTable class PaddleReadClock`.
- **Зависит от:** `10_math`. Потребители: `40_swipe 56_rig 70_game`.
- **Можно ли отдать:** относительно изолирован. Тесты `paddle-motion.test.js`. Держать экспортные имена.

### `40_swipe.js` — 🔴 ядро ввода→удара
- **Назначение:** жест превращается в реальное состояние ракетки (3-D скорость + нормаль грани + точка контакта); мяч резолвится rigid-body solvers'ом. `deriveStroke`, `classifyStroke`, `solveServeStroke`, `solveBlockNormal`, `refineRacket`, `shotReport`.
- **Глобалы:** `class SwipeTracker STROKES ARCH isRealStroke classifyStroke deriveStroke launchPoint dirFromAngles strokeFrame SERVE_VMAX … solveServeStroke solveBlockNormal refineRacket shotReport`.
- **Зависит от:** `10_math 12_match_rules 30_physics`. Потребители: `70_game`.
- **Можно ли отдать:** высокое влияние, но интерфейс к game узкий. Переписка допустима при сохранении `deriveStroke/refineRacket/shotReport`. Тесты `gestures.test.js`.

### `42_shot_diagnostics.js` — 🟢
- **Назначение:** доказательная обратная связь по удару (intent≠contact≠возврат≠очко), калибровка зон. Хранит только числа, не кадры.
- **Глобалы:** `SHOT_DIAGNOSTICS_VERSION SHOT_OUTCOMES measureShotSpin shotSpinText shotFeedbackView shotHudView class ShotJournal calibrationPercentile class ZoneCalibrationSession shotCalibrationCases evaluateShotCalibration summarizeCaptureCalibration`.
- **Зависит от:** `10_math`. Потребители: `80_ui`, `70_game`.
- **Можно ли отдать:** хорош для делегирования. Тесты `shot-diagnostics.test.js`. Версию `SHOT_DIAGNOSTICS_VERSION` поднимать при смене схемы.

### `43_input_telemetry.js` — 🟢
- **Назначение:** ограниченный лог решений указателя за 30 с (ring buffer), JSON только на экспорт.
- **Глобалы:** `INPUT_LOG_SCHEMA INPUT_LOG_SECONDS INPUT_LOG_MAX_EVENTS inputLogVec inputLogDecision class InputTelemetryLog makeInputLogEvent benchmarkInputTelemetry`.
- **Зависит от:** `10_math`. Потребители: `70_game`/diagnostics.
- **Можно ли отдать:** автономный, безопасный кандидат.

### `50_audio.js` — 🟢
- **Назначение:** весь звук синтезируется в рантайме; тембр удара из физики (импульс/слип/материал). Записанные сэмплы декодируются с `window.__AUDIO_SAMPLES__` с фолбэком в синтез.
- **Глобалы:** `spectatorClapPlan class AudioEngine`.
- **Зависит от:** `10_math`. Потребители: `70_game 75_feedback`.
- **Можно ли отдать:** изолирован. Держать метод `AudioEngine.ui()`/`setVolume()`, которые вызывает game/ui.

### `55_ai.js` — 🟡
- **Назначение:** соперник — анимация удара только ракеткой, читаемость (commit ~0.3 s, видимый backswing), уровни/тактики.
- **Глобалы:** `AI_LEVELS AI_TACTICS AI_BACKSWING shotHitsNet makeRacket class OpponentAI`.
- **Зависит от:** `10_math 30_physics 40_swipe 56_rig 38_paddle_motion`. Потребитель: `70_game`.
- **Можно ли отдать:** переписка возможна при контракте `OpponentAI` (`setHandicap` и т.п. вызываются game). Тесты `ai:*`/`core`.

### `56_rig.js` — 🟡
- **Назначение:** поз ракетки (shakehand), локаль +Z = нормаль красной грани, -Y рукоять. Чистый потребитель gameplay-позы.
- **Глобалы:** `playerWristPose faceFromWrist class PaddleRig`.
- **Зависит от:** `10_math 38_paddle_motion`. Потребители: `60_scene 70_game`.
- **Можно ли отдать:** визуальный слой, относительно безопасно. Держать `PaddleRig` API для scene.

### `57_camera.js` — 🔴 ядро кадрирования/hit-test
- **Назначение:** пресеты стабильной камеры + независимые высота/dolly; headroom включает ракетку и подброс соперника; **матрицы рендера и hit-test/HUD делят один framing-shift**.
- **Глобалы:** `CAMERA_PRESETS CAMERA_ORDER PADDLE_LIMITS effectiveFov phoneFactor frameMargin cameraHeadroom frameBottomRoom rigViewProj projectPoint FRAME_POINTS PADDLE_POINTS REACH_* rigMargin paddleVolumeVisible FIT_MARGIN fitRig cameraRigFor TABLE_FRAME_POINTS tableScreenBounds OPPONENT_FRAME_POINTS CAMERA_HEADROOM opponentScreenTop tableFrameShift`.
- **Зависит от:** `10_math 30_physics(PH)`. Потребители: `70_game` (project), `80_ui`.
- **Можно ли отдать:** **хрупко** — `paddleTargetFromPointer` обязан оставаться точной обратной проекции (`camera.test.js` проверяет errXY<0.02). Кадрирование править только с прогоном `camera.test.js` (14 тестов). Не менять `PADDLE_LIMITS` вслепую.

### `58_coach.js` — 🟢/🟡
- **Назначение:** три системы — `RallyRecorder` (запись розыгрыша), `PointAnalyst` (разбор почему проиграно), `MatchDirector` (динамический гандикап).
- **Глобалы:** `class RallyRecorder ANALYSIS class PointAnalyst class MatchDirector`.
- **Зависит от:** `10_math`, читает состояние game. Потребители: `70_game 80_ui`.
- **Можно ли отдать:** хорош для делегирования; аналитика — потребитель, не источник истины физики. Держать `director.enabled/reset`, `ai.setHandicap` контракты.

### `59_replay.js` — 🟢
- **Назначение:** «лучшие моменты» — ring buffer + фильтр красоты, не «видео всего».
- **Глобалы:** `REPLAY_HZ REPLAY_RING_S REPLAY_FLOATS REPLAY_KEEP BEAUTY class MomentRecorder class MomentPlayer`.
- **Зависит от:** `10_math`. Потребители: `70_game 80_ui`.
- **Можно ли отдать:** изолирован, безопасный кандидат.

### `60_scene.js` — 🟡
- **Назначение:** вся геометрия и текстуры генерятся в рантайме; размеры по ITTF (стол 2.74×1.525×0.76, сетка 15.25 см). Процедурные текстуры + `class Scene`.
- **Глобалы:** `cv texTableTop texFloor texNet texBall texRubber texBanner texWall texShadow texGlow texRing PALETTES class Scene`.
- **Зависит от:** `10_math 20_gl 30_physics(PH) 56_rig`. Потребитель: `70_game`.
- **Можно ли отдать:** переписку визуала можно, если `Scene` сохраняет метод сборки мешей, который ждёт game/Renderer.

### `65_train.js` — 🟡
- **Назначение:** интерактивный тренер, один дрилл за раз; прогресс по реальному spin/speed + легальный отскок. `TRAIN_STEPS` (у каждого `guide` — форма жеста для визуальной подсказки). Демонстрация `TrainerDemo` запускается ТОЛЬКО кнопкой «ПОКАЗАТЬ, КАК ИГРАТЬ» (`Trainer.playDemo`) и ведёт настоящий ввод через `demoPress/demoMove/demoRelease`, поэтому правила допуска и захвата те же, что у игрока.
- **Глобалы:** `detectInputMode trainingTip TRAIN_STEPS class Trainer class TrainerDemo`.
- **Зависит от:** `10_math 12_match_rules 30_physics`, вызывает game (`prepServe`, `applyHit`, `onBounce`). Потребители: `70_game 80_ui` (`drawTrainDemo`).
- **Можно ли отдать:** добавление нового шага = элемент в `TRAIN_STEPS` (обязательны `id goal title need guide tip mouseTip feed check failHint`). Тесты `training.test.js`.

### `70_game.js` — 🔴 ядро-оркестратор (самый большой, ~2991 стр.)
- **Назначение:** state-машина `GS`, правила ITTF, непрерывная детекция коллизий, rig-камера, VFX/частицы, рекордер реплеев, настройки/сохранение, подача. `class Game`, `class Particles`.
- **Глобалы:** `AI_SERVE_CONTACT_Y GS PHYS_DT defaultGestureProfile class Particles class Game hexToRgb`.
- **Зависит от:** почти всего. **Потребители:** `80_ui 90_boot` (и косвенно все).
- **Можно ли отдать:** **главный «не трогать без координации».** Здесь живёт контракт `game.project`, стейт-машина, `settings/save/load`. Подмодули (training/ai/coach/camera) вызываются отсюда — их можно менять, сам Game — с осторожностью. `serveToss` настройки: default/`saveSettings`/`loadSettings.ranges`/`startToss` — четыре согласованных места.

### `75_feedback.js` — 🟢
- **Назначение:** многослойная обратная связь удара: визуал (частицы/вспышка), аудио-слои, haptics, микро-реакция камеры.
- **Глобалы:** `class HitFeedbackSystem`.
- **Зависит от:** `10_math`, читает physics-события; дергает `50_audio`. Потребитель: `70_game`.
- **Можно ли отдать:** изолированный «потребитель», хорош для делегирования.

### `75_music.js` — 🟢
- **Назначение:** динамический эмбиент-саундтрек (base pad / tension / climax / resolution).
- **Глобалы:** `class MusicSystem`.
- **Зависит от:** `10_math`, WebAudio. Потребитель: `70_game`.
- **Можно ли отдать:** полностью изолирован. Безопасно переписывать.

### `76_emotion.js` — 🟢
- **Назначение:** эмоциональная драматургия (match point, камбэк, празднование, сетка/рёбро).
- **Глобалы:** `class EmotionalSystem`.
- **Зависит от:** `10_math`, читает game-события. Потребитель: `70_game`.
- **Можно ли отдать:** изолирован, безопасный кандидат.

### `80_ui.js` — 🟡 (большой, ~1574 стр.)
- **Назначение:** HUD, меню, 2D-тренерский слой на fx-canvas. Один shot-badge, один счёт, тайминг-скобки на мяче. Оверлеи: `drawStrikeRing drawAimReticle drawTrainDemo drawTrainGuide drawCaptureDebug` (всё в `drawOverlay`).
- **Глобалы:** `$ $$ class UI CSSFONT roundRect ICON`.
- **Зависит от:** `70_game 12_match_rules 65_train …`. Потребители: `90_boot`.
- **Можно ли отдать:** рисование оверлеев модульное (каждый `draw*` — готовая точка делегирования). **Но** биндинг настроек (`applySetting/syncSettings`, `.opt`/`input[data-set]`) связан с `70_game.settings` и `02_body.html`. Тесты `lifecycle/controls`. `drawAimReticle` — прицел в режиме без ракетки (гейт `showPlayerPaddle===false`), `drawTrainGuide` — визуальный жест (`tr.S.guide`).

### `81_uiAnim.js` — 🟢
- **Назначение:** анимации UI: переходы чисел, появления элементов, микровзаимодействия, HUD-анимации.
- **Глобалы:** `class UIAnimation class HUDAnimation`.
- **Зависит от:** `10_math`, DOM. Потребители: `80_ui`.
- **Можно ли отдать:** изолированный хелпер, безопасный.

### `84_racket.js` — 🟡
- **Назначение:** снаряжение (клинки/накладки). Каждый предмет — набор реальных физических параметров (COR, трение, dwell, sweet-spot, swing weight) в `impactRacket`. Числа на карточке **производны от физики**, статы в одном бюджете (никто не «сильнее»).
- **Глобалы:** `STAT_MIN/MAX/KEYS/RU spread statK BLADES RUBBERS bladePhysics rubberPhysics ITEMS ITEM_LIST ITEMS_ORDER itemStats racketStats class Equipment`.
- **Зависит от:** `10_math`, отдаёт параметры в `30_physics`. Потребители: `86_meta 70_game`.
- **Можно ли отдать:** баланс/каталог править можно, не трогая контракт «физические параметры → impactRacket». Тесты `paddle.test.js`.

### `86_meta.js` — 🟡
- **Назначение:** коммерческий слой — профиль, деньги, магазин, платформа, save. Правила: ничего не влияет на победу; без dark patterns.
- **Глобалы:** `SAVE_KEY SAVE_VERSION MAX_* safeAssign num int bool class Platform class Analytics DAILY_TASKS class Profile COSMETICS SHOP_BUNDLES class Shop ECONOMY`.
- **Зависит от:** `10_math 84_racket`. Потребители: `70_game 80_ui`.
- **Можно ли отдать:** изолирован по смыслу; менять `SAVE_KEY/SAVE_VERSION` аккуратно (миграция сохранений). Тесты `core/lifecycle`.

### `90_boot.js` — 🔴 (маленький, но критичный, ~124 стр.)
- **Назначение:** старт: создание Game/Renderer/UI/всех систем, `window.__game`, Telegram-host мост (единственный внешний скрипт, `disableVerticalSwipes`), splash.
- **Зависит от:** всего.
- **Можно ли отдать:** менять порядок/условия инициализации — только с ручным прогоном (порядок создания систем важен). Функционально мал, правки точечные.

### `02_body.html` — 🟡

# Scene, Playfeel and Match UI

Status: implementation-ready plan. Design choices below are confirmed; execution requires switching to an implementation-capable agent. Only this plan file was changed during planning, and no builds or tests were run in plan mode.

## Goal and Constraints

- Black table net with white tape at the top; clean table end views and an aged outdoor appearance.
- Readable, materially distinct standard paddle and pan under all normal orientations and quality settings.
- A deliberate mouse-circle trick: no held button, approximately 20 cm toss, 540-degree spin and opposite-face catch.
- Deeper, firmer ordinary AI returns; easier curved gestures; clearly observable, physically computed spin trajectories.
- Correct, consistent ball/table audio, including the far side.
- A substantially smaller live HUD and a fully redesigned result report that includes real stroke statistics.
- Preserve the current uncommitted GLB/catalog work, supplied paddle atlas, pan playing-bottom alignment, mobile/desktop scene parity and existing gameplay/reward invariants.
- Edit canonical `source/src/` and `source/game/tt/src/`; generate only the published `play/index.html` through `python3 source/build.py`. Never duplicate HTML edits or reset unrelated changes.

## Confirmed Decisions

- The user selected strong arcade-like curves, not restrained realistic curvature. The stronger turn must affect the actual integrated flight, with the accompanying pace/control trade-off; it is not a cosmetic path overlay.
- Fix unintended short/weak AI returns across all four difficulties. Retain their different reaction, error and effort limits, and occasional purposeful short tactics; do not make beginner bots as strong as HARD/WTF.
- HUD scope is only the upper-left scoreboard and match-progress block. The user explicitly said not to touch the right-side menu/controls. Keep notifications, slow-motion inspector and Pause in their current locations with their existing behavior.
- The trick remains paddle-only. Convey the catch by the paddle's brief landing/settle; do not add a hand or character model.
- Side-switch trick applies only to the standard two-face racket. The user selected keeping the pan's single supported outside playing bottom; no inner-bowl gameplay or pan flip is added.
- Keep the current painted table model, dimensions and main palette. Give it a faded matte outdoor finish, worn/chipped edges and restrained weathering/corrosion on the frame; do not replace it with a massive concrete table.
- Result report uses the same single-column composition on mobile and desktop. The user rejected a desktop two-column variant; keep the existing centering/frame policy and do not add a wider desktop-only layout.
- Distinguish short table and racket contact sounds. Use the same dry table timbre on both courts, one transient per actual contact and only mild positional variation; no muffled or disappearing opponent table cue.

## Verified Context

- `10_math.js:153-162`: `M4.normalFromMat4` returns an inverse rather than the promised inverse-transpose; rotated meshes therefore receive incorrect lighting normals. Fix before tuning lights.
- `60_scene.js:70`: the white net strip is painted near the bottom of the canvas. Net texture upload flips Y; quad UVs put v=1 at the top. Paint the strip at canvas y=0, not by changing global upload orientation.
- `60_scene.js:247,272,452`: one tabletop texture is applied to all six box faces. End faces compress the entire tabletop markings into the slab thickness. Aprons also overlap the slab by 7 mm and protrude at corners (`329-339`). Box winding is already correct; cylinder cap winding is not (`20_gl.js:113-114`).
- Shadow maps are disabled. Black paddles are not established shadow-map acne: investigate transformed normals, imported materials, ambient response and strong vignette instead. Existing shaders already flip backface normals.
- HARD already intends ordinary landings approximately 1.02-1.26 m beyond the net. The solver can blend toward a raw net marker, and AI effort reduction happens after solving; first-legal rescue returns can be short. Frequency still needs measurement.
- Magnus acceleration is already active in `30_physics.js:116-193`, using SI units and `omega cross velocity`. Pure vertical-axis sidespin bends flight but does not itself create a horizontal-table side kick. Do not add fake render-only arcs.
- C recognition combines turn, path/chord >=1.15 and other gates; sensitivity alone does not relax all of them. Real contact may consume a straight prefix before the C is completed. Current coalescing tests suppress contact and miss this case.
- Player racket sound has two actual dispatch owners: feedback and `applyHit`. Table dispatch is separate and uses pre-bounce normal speed. Shared racket/table samples and no world-Z distance mix warrant listening tests, but an opponent-specific table defect is not yet proven.
- Canonical HUD is `source/src/ui/match_hud.js`, not `live_match_ui.js`. Both players' confirmed contacts already export technique, km/h and total revolutions/s.
- Match-end payload already contains stroke dictionaries and opponent telemetry, but `screens/match.js:184-194` drops them. Engine aggregates reset after iframe recovery, and passive blocks miss some maxima; do not present those fields as complete match statistics blindly.

## Contracts, Migration and Failure Cases

- No intended changes to saved inventory, marketplace, purchases, ranking, reward formulas or server API. Retain the current v10 inventory migration; do not introduce a save migration for cosmetic HUD state.
- Trick state is not a physical racket toss that can hit or carry the ball. It is a paddle-only presentation plus a committed face selection when no ball is live. No trick in live rallies, no hand asset, no pan/inner-bowl surface and no new touch gesture are in scope.
- Full sRGB/IBL/normal-map/ORM overhaul, new characters, concrete-table replacement, desktop-only two-column results, right-side menu redesign, new touch trick, online protocol redesign and persistent reopened match reports are outside scope.
- Result summaries may be partial after lost contact coverage. No inferred spin direction from family names, invented opponent accuracy/winners, or fabricated demo distributions. AI speed telemetry is m/s and needs conversion.
- Do not use debug journals as an unbounded ordinary match database. Replay/cached snapshots must not count contacts twice.
- All time-based animation and cancellation should agree at 30/60/120 Hz; render must not change simulation pose or trigger a collision/audio event.

# Table Tennis Ultimate — v2 (game-grade redesign)

**Результат:** `index.html` — один самодостаточный файл (~1.7 МБ: оболочка + встроенный WebGL-движок). Без CDN, без внешних шрифтов и картинок. Работает офлайн, в Telegram и в превью-iframe.

## Структура

Полное описание слоёв, контрактов (i18n, сейвы, каталог, протокол хост↔движок) и «как добавить экран/товар/язык» — в [`docs/ARCHITECTURE.ru.md`](docs/ARCHITECTURE.ru.md). Кратко:

```
source/
  build.py            → собирает src/* в index.html (инлайнит шрифты/аватары/CSS/JS + GAME_HTML движка)
  src/index.tpl.html  каркас + #device
  src/core/           util · i18n · state (сейвы v2) · platform (Telegram) · audio · ui_core (роутер/шиты) · dev
  src/locales/        словари ru.js / en.js — весь видимый текст только через t('key')
  src/data/           leagues · catalog (маркетплейс) · season — чистые данные
  src/ui/             art · item_art · bg · fx · ui — переиспользуемый рендер
  src/services/       economy · career · game_host (мост postMessage в движок)
  src/engine2d/       2D-демо хаба (фолбэк без WebGL)
  src/screens/        один файл = один экран: hub · matchmaking · match · training · result · shop · pass · ranks · profile · settings
  src/css/            base.css + screens_{hub,battle,meta,misc}.css
  src/main.js         сплэш + загрузка (последний в порядке сборки)
  game/               WebGL-движок (свой build: game/tt/build.py, тесты: npm test в game/ и в source/)
```
Пересборка: `python3 build.py`. Открыть экран напрямую: `index.html?s=shop` (`hub, mm, vs, match, result, chest, shop, pass, ranks, profile`).

**Связь с сервером (необязательна).** Адрес Game API вшивается при сборке, потому что бандл статический: `TT_API_BASE=https://api.example python3 build.py`. Без переменной клиент работает полностью локально — это штатный режим, а не ошибка. Для отладки адрес можно перекрыть ссылкой: `index.html?api=http://localhost:4100`.

Клиент тянет авторитетное расписание сезонов с сервера (`GET /api/client/v1/liveops/events`) независимо от Telegram-входа: даты и полную сетку наград. Последний проверенный календарь хранится в `ttu-seasons` и работает офлайн, включая переход к запланированному сезону; хардкодный сезон 4 (15.10–10.11.2026) нужен только до первой успешной загрузки. Календарь обновляется раз в минуту, на границах сезона и при возвращении в приложение. Rollover вперёд сбрасывает `passLvl/passXp/premium/claimed` и сразу сохраняет новый `passSeason` (сейв v6); карьерный опыт, рейтинг, кошелёк и инвентарь остаются. Закрытый сезон нельзя купить или клеймить, открытый экран перерисовывается без перехода. Календарь read-only: серверное хранение прогресса пропуска и реальная оплата Stars ещё не подключены.

## Честно о пределах
- Это прототип на DOM/Canvas2D: до AAA не хватает настоящего 3D, анимированных персонажей, профессионального саунд-дизайна и сотен итераций плейтестов.
- Платежи (Stars), онлайн-матчи, друзья — демо-заглушки без бэкенда.
- Тестировалось в headless Chromium 390×844; на реальных iOS/Android в Telegram нужен прогон на устройстве.

## Фаза 2 — настоящий движок, интро/аутро, новое обучение, зона удара

**Движок.** Игрушечный матч заменён настоящей игрой из `hudyakovictor/tabletennis` (TOPSPIN ARENA, WebGL).
Исходники лежат в `game/` (тесты: `cd game && node --test`). `build.py` сам собирает игру и встраивает её
в `index.html` как строку для `iframe srcdoc`: остаётся один файл, внешних зависимостей нет.
Мост `game/tt/src/92_embed.js` + `06_embed.css` включаются только при `window.__TT_EMBED`; в таком режиме
счёт, баннеры, пауза и итог рисует v2. Если открыть игру отдельно, она работает как раньше.

Протокол postMessage: хост → игра: `attract · prematch · match · train · pause · resume · quit · outro · replay ·
skipReplay · skipStep · hint · debug · mute · quiet`; игра → хост: `ready · state · serve · hit · point · matchEnd ·
train · trainDone · paused · replayEnd · haptic`.

**Интро и аутро.** Поиск соперника → VS. Затем камера движка облетает стол под кинополосами, выезжают плашки
игроков и «Матч до N», идёт отсчёт 3-2-1 «Игра!». В конце: «Победа/Поражение» со счётом, облёт камеры,
повтор лучшего розыгрыша (его можно пропустить), экран итога.

**Обучение** (`?s=train`; запускается при первом нажатии «В бой»; режим «Тренировка» на Арене):
1. Удар. Первый мяч **замирает** в точке удара. Кольцо показывает честный размер зоны, «призрачный палец»
   показывает свайп. Мяч отпускает только нажатие, которое засчитала бы игра; промах встряхивает кольцо.
2. Направление. Подсвечивается половина стола, свайп нужно вести по диагонали.
3. Подача. Тап подбрасывает мяч, он замирает на падении, дальше свайп.
4. Топспин, 5. Подрезка, 6. Закрепление без подсказок.
Подсказки убираются по одной (стоп → сходящееся кольцо → только кольцо) и возвращаются после двух промахов подряд.

**Зона удара (контракт v3)**: захват 0,62 → 0,22 м, допуск глубины 0,62 → 0,22 м, подача 0,88 → 0,55 м.
Зона нажатия теперь стоит в предсказанной точке встречи (вниз 100 px, вверх 36, по бокам ±46 тач / ±34 мышь).
Контакт засчитывается в точке наибольшего сближения мяча с ракеткой. Отладка: `?dev=1` (кнопка-мишень
на матче и в обучении) или десктоп-панель «Движок → Зона удара». Там ползунки, «Показать зоны» и автошаг.
Значения хранятся в `localStorage['ttu-rules-dev']` и передаются движку через `__TT_RULES`.
Карты эффективной зоны: `game/tools/hitmap.py`.

### Сквозные проверки (`tools/e2e`, нужен `pip install playwright`)
- `tdet.py` — обучение «Удар» (стоп-мяч, нажатие мимо, 3 мяча) + первый мяч «Направления».
- `tserve.py` — подача в обучении (тап → стоп на падении → свайп).
- `tlead.py` — окно по времени: за сколько секунд до встречи палец ещё успевает.
- `tfull.py` — полный матч до 7 с ботом (`bot2.js`): счёт, матчбол, финал, повтор, экран итога.
- `tblur.py` — кнопки хоста не ставят игру на паузу; «Пауза» в матче ставит и снимает.

### Лобби и бот
- На Арене за интерфейсом идёт настоящий матч «бот против бота». Камера облетает стол, звука нет, счёт и сообщения игры скрыты. На качестве «Эконом» вместо него остаётся лёгкая 2D-заглушка. Движок начинает загружаться ещё во время сплэша.
- Бот режима наблюдения переписан под контракт v3: он читает ту же точку встречи, что и кольцо-подсказка, и ведёт свайп через неё (лучший розыгрыш в прогоне — 21 удар).

## Статистика зоны удара (данные с реальных телефонов)

Подбирать размер зоны «на глаз» неудобно, поэтому игра теперь логирует каждую **попытку**, то есть нажатие на летящий к тебе мяч (касание для подброса при подаче не считается):

| поле | смысл |
|---|---|
| `dx, dy` | где лёг палец относительно точки встречи, px (+y = ниже) |
| `lead` | за сколько секунд до встречи было нажатие |
| `accepted` | попал ли палец в овал зоны |
| `contact`, `sweet` | был ли контакт и насколько точный |
| `reason` | `TIMING_LATE`/`DEPTH_FAIL`: палец в зоне, но ракетка прошла мимо мяча; `TIMING_EARLY`/`NO_FRESH_SWIPE`: свайп закончился слишком рано; `POINT_*`: розыгрыш кончился без контакта |

* Игра: `onPressZone` в `70_game.js` → `92_embed.js` (обёртки `logPressRejection`, `applyHit`, `setState`, `awardPoint`) → сообщение `attempt` в хост. В лобби и демо попытки не пишутся.
* Хост: `ZoneStats` в `game_host.js` хранит последние 300 попыток в `localStorage['ttu-zone-stats']`.
* UI (`&dev=1`): в матче кнопка ◎ → «Статистика попаданий», либо dev-панель → «Статистика». На экране:
  * облако точек вокруг овала: зелёная = контакт, красная = палец в зоне, но промах, серая = мимо зоны;
  * гистограмма `lead`;
  * проценты;
  * рекомендации:
    * мимо зоны > 25% → расширить бока на N px (N считается по медианному промаху);
    * ракетка мимо > 20% → радиус захвата +0,02–0,04 м;
    * рано > 15% → включить подсказку;
    * контакт > 85% при n ≥ 30 → можно ужать радиус.
  * Кнопка «Настроить зону» сразу открывает слайдеры.
* Порядок работы: дай телефон 3–5 людям, пусть сыграют по матчу, открой статистику, примени рекомендацию в «Зона удара» и повтори.
* e2e: `tools/e2e/tzstats.py`. Бот с «человеческим» разбросом (`window.__b2jit = {px, lead}` в `bot2.js`) играет, пока не наберёт 38 попыток, потом открывает лист статистики и сохраняет `shots/z_stats.png` и `shots/z_attempts.json`.
* Также в `tools/e2e`:
  * `thub.py`: лобби хаба с ботами;
  * `tfrz.py`: стоп-кадр обучения и касание для подачи;
  * `tdemo.py`: демо «бот против бота». Ему нужна отдельная сборка игры: `cd game && python3 tt/build.py ../game_build.html`.

## Советы после промаха, награда за обучение, «Меньше движения»

* **Советы в матче.** Раньше после промаха показывалось просто «Нет контакта». Теперь та же плашка внизу экрана жёлтым объясняет, что исправить. Совет строится из той же записи попытки, что и статистика зоны:
  * палец вне зоны:
    * выше мяча → «Начинай свайп ниже мяча — снизу вверх»;
    * сбоку → «Палец левее/правее мяча — ставь его прямо под мяч»;
    * слишком низко → «Слишком низко — начинай ближе к мячу»;
  * рано (`TIMING_EARLY` или нажатие больше чем за 0,2 с до встречи) → «Рано! Дождись, пока мяч подлетит к тебе»;
  * ракетка прошла сбоку от мяча → «Ракетка прошла левее/правее — веди свайп прямо через мяч»;
  * нажатия не было, а мяч уже отскочил на твоей стороне → «Мяч пропущен — свайпни снизу вверх через него».
  * Если контакт был, но мяч ушёл в сетку или в аут, к статусу добавляется «свайп круче вверх» / «короче и мягче».
  * Плашка стала компактной (не больше 100vw−150px) и не залезает под угловые кнопки.
  * В обучении советов нет: там свой тренер.
* **Награда за обучение.** На карточке «Готов к матчу!» монеты (+200) и кристаллы (+5) летят из кубка в счётчики. Награда выдаётся один раз (`S.tutorialRewarded`). При повторном прохождении на карточке написано «уже получена».
* **«Меньше движения».** Настройка передаётся в игру (сообщение `rm`). Облёт камеры в меню и лобби замедляется в 5 раз, победный облёт идёт без вращения. Системная настройка `prefers-reduced-motion` тоже учитывается.
* e2e: `tools/e2e/ttips.py`. Бот с сильным разбросом собирает советы и сохраняет `shots/t_tip.png`, потом проверяет награду в обучении (`t_reward*.png`). Внимание: в headless-режиме requestAnimationFrame внутри iframe почти не работает, поэтому скрипт сам вызывает `__game.ui.tick`.

## Адаптивное кольцо, «Разбор матча», сон скрытой игры

* **Адаптивное кольцо.** Если «Подсказка удара» выключена и игрок промахнулся 3 раза подряд (промахом считается и пропущенный мяч), кольцо в точке встречи включается само. Появляется совет «Включил кольцо: веди свайп через него». После двух чистых контактов кольцо снова скрывается. Настройку игрока это не меняет. Сообщение в хост: `autoHint {on}`.
* **«Разбор матча» на экране результата.** Берутся только попытки этого матча (`ZoneStats.matchSummary(BATTLE.t0)`):
  * процент контакта;
  * главная ошибка — одна из четырёх: палец уходит вбок, свайп начинается выше мяча, удар раньше времени, ракетка проходит мимо;
  * как её исправить;
  * мини-карта точек;
  * при ≥ 80% контакта — «Чистая техника» и следующий шаг (вращение).
  * Если попыток меньше трёх, показывается общий совет.
* **Кнопки результата закреплены внизу** (sticky): «Далее» и «Реванш» видны, даже когда карточки не помещаются в экран.
* **Сон скрытой игры.** Раньше iframe с WebGL рендерил на полной частоте за магазином, профилем и результатом: лишний расход батареи и подтормаживание анимаций интерфейса. Теперь через 0,6 с после скрытия слоя хост шлёт `sleep`, и `update`, `render`, `ui.tick` пропускаются. При показе слоя приходит `wake`; любая игровая команда тоже будит игру. Под нагрузкой swiftshader анимации экрана результата раньше застревали на первой медали, теперь проигрываются полностью.
* e2e:
  * `tcoach.py`: матч с сильным разбросом → адаптивное кольцо и экран результата;
  * `tresult.py`: быстрый экран результата по `z_attempts.json`;
  * `twake.py`: хаб → магазин (игра стоит) → хаб (лобби снова идёт) → матч.

## «Техника удара» в профиле

* После каждого матча, в котором было хотя бы 3 попытки, итог «Разбора матча» сохраняется в `localStorage['ttu-match-log']` (последние 30): `{t, pct, n, win, key}`.
* Карточка в профиле показывает:
  * столбики точности контакта за последние 12 матчей: зелёный = победа, серый = поражение, последний обведён золотом;
  * текущий процент и разницу со средним по прошлым матчам;
  * самую частую ошибку («Чаще всего: ракетка проходит мимо мяча (5 из 10)»).
* Если матчей ещё нет, показывается пустое состояние с приглашением сыграть.
* Столбики вырастают пружинной анимацией, при «Меньше движения» — сразу.
* e2e:
  * `tautohint.py`: полный цикл адаптивного кольца в реальном матче. Бот с разбросом включает кольцо (при счёте 0:3), точный бот выключает его после двух контактов, `hintContact` возвращается в `false`. Матч доигрывается и попадает в журнал техники.
  * `tprofile.py`: пустое состояние и визуальная проверка карточки на 10 искусственных матчах.

## Карьера: настоящий «Стиль игры» и достижения

* `src/career.js`. Раньше профиль рисовал радар и достижения из заглушек. Теперь они считаются только по сыгранным матчам (`S.car`, `S.ach`).
* **Радар «Стиль игры».** Чтобы радар не скакал после первого матча, каждая ось смешивается с нейтральным значением: вес нейтрального значения равен 2 матчам, вес данных растёт с числом матчей.

  | ось | как считается |
  |---|---|
  | Подача | очки, выигранные на своей подаче / все свои подачи |
  | Атака | (идеальные + смеши) / удары × 1,6 |
  | Защита | твои ответные удары / удары соперника |
  | Вращение | удары с вращением (`LOOP, COUNTER, FLICK, PUSH, CHOP, HOOK, FADE, LOB`) / удары × 2 |
  | Реакция | контакт / попытки (`ZoneStats`) |

* **Шесть достижений:**
  * «Первая победа»;
  * «Серия 3»: 3 победы подряд;
  * «Снайпер»: контакт 80%+ за матч, от 10 попыток;
  * «Марафонец»: розыгрыш из 15+ ударов;
  * «Ювелир»: 5 идеальных ударов за матч;
  * «Мастер вращения»: 10 ударов с вращением за матч.
* На экране результата каждое новое достижение по очереди выезжает золотой плашкой сверху (иконка с поворотом, искры, звук, хаптика). Плашку можно закрыть касанием.
* В профиле счётчик «N / 6». Касание по достижению показывает его условие.
* Если в матче контакт хороший, но матч проигран, «Разбор матча» советует целиться в углы, а не учить вращение.
* **Запуск всех e2e:** `python3 tools/e2e/run_all.py` (быстрый набор, около 7 минут, 11 скриптов по очереди) или `--long` вместе с долгими прогонами. Скрипт считается упавшим при ненулевом коде выхода, таймауте или ошибке страницы. Большинство скриптов только печатают состояние и сохраняют скриншоты, поэтому вывод и `shots/` нужно смотреть глазами.
* `tcareer.py`: реальный матч точным ботом → достижения «Снайпер», «Марафонец», «Ювелир», «Мастер вращения» → профиль «4 / 6» и радар по 1 матчу.

## A/B-настройка зоны: подпись, сравнение, ссылка, экспорт

* **Подпись зоны в каждой попытке.** Игра пишет в запись поле `sig = бока/верх/низ/радиус` (например `46/36/100/0.22`). Раньше попытки при разных настройках смешивались в одну статистику. Теперь лист «Статистика зоны» по умолчанию показывает только **текущую зону**, а переключатель «Все настройки» показывает всё вместе.
* **«Сравнение настроек».** Таблица всех зон, на которых играли: процент контакта, процент мимо зоны и число попыток. Лучшая зона среди тех, где было 10+ попыток, обведена зелёной рамкой, текущая отмечена жёлтой точкой. Старые записи без подписи идут строкой «до записи настроек».
* **Ссылка с настройкой.** Кнопка в листе «Зона удара» копирует ссылку `…/index.html?rules=<base64url JSON>`. В Telegram то же самое работает через `startapp=r_<base64url>` (параметр `start_param`). При открытии ссылки:
  * значения обрезаются по диапазонам слайдеров, неизвестные ключи отбрасываются;
  * настройка сохраняется в `ttu-rules-dev`, и движок стартует уже с ней;
  * тост показывает, что применилось («Зона из ссылки: r 0.26 · верх 100 · бока 40»);
  * сброс — «Сброс v3».
* **«Экспорт JSON».** Копирует в буфер `{exported, ua, screen, rules, attempts}`, чтобы тестер мог вставить данные в чат.
* **Порядок работы:**
  1. Подбери зону.
  2. Нажми «Ссылка с настройкой» и разошли тестерам.
  3. Тестеры играют и присылают «Экспорт JSON».
  4. Сравни зоны в таблице.
  5. Победившую зону закрепи значениями по умолчанию в `12_match_rules.js`.
* e2e `tlink.py`:
  * ссылка с `{side 40, r .26, back 999, evil 5}` → в движке 40 / 0.26 / 100 (back обрезан), `evil` отброшен;
  * новые попытки реального матча пишутся с подписью, совпадающей с текущей;
  * таблица сравнения из 2 строк, экспорт копирует, кодирование ссылки обратимо.

## Устойчивость: потеря WebGL-контекста и поворот телефона

* **Потеря GPU-контекста.** Мобильные браузеры сбрасывают WebGL при сворачивании приложения или нехватке памяти. Раньше после этого арена оставалась чёрной навсегда. Теперь:
  * игра ловит `webglcontextlost` и сообщает хосту `glLost {state, inMatch, score, server, training}`;
  * хост показывает «Восстанавливаем арену… · Счёт сохранён», пересоздаёт iframe и повторяет последнее состояние: качество, звук, подсказку, «меньше движения», debug, паузу и режим;
  * матч продолжается с тем же счётом и подающим, без пролёта камеры (`match {resume}`), лобби снова запускает бота, обучение возвращается на тот же шаг;
  * если контекст теряется третий раз за минуту, качество автоматически снижается до low;
  * если слой скрыт, восстановленная игра сразу засыпает.
* **Поворот телефона.** На сенсорном экране в горизонтальном положении с высотой до 520 px поверх приложения появляется экран «Поверни телефон» с анимацией. Идущий матч или обучение при повороте ставятся на обычную паузу с листом «Пауза». В Telegram (Bot API 8.0+) дополнительно вызывается `lockOrientation()`.
* e2e `tgl.py`:
  * потеря контекста через `WEBGL_lose_context` в матче при 0:3 → тот же счёт 0:3 и подающий, игра продолжается до 0:5, табло хоста совпадает;
  * лобби: бот снова играет;
  * обучение: шаг 2 → шаг 2;
  * горизонтальный экран: оверлей виден;
  * поворот посреди матча: лист паузы открыт, игра на паузе.

## Запуск и фоновая нагрузка

Замеры: `tools/e2e/tperf.py [замедление CPU]`, песочница, Chromium headless.

| | было | стало |
|---|---|---|
| заставка → хаб, CPU ×1 | 9,7 с | 5,1 с |
| заставка → хаб, CPU ×4 (средний телефон) | 11,0 с | 6,5 с |
| движок готов к моменту входа в хаб | да | да (за 2,3 с до входа) |
| 3D-рендер за заставкой и поиском соперника | шёл на полной частоте | спит (время игры +0,00) |

* **Почему заставка была долгой.** Iframe игры создавался под заставкой и сразу рендерил облёт стола на полной частоте, хотя слой скрыт. Таймеры заставки голодали в общем главном потоке.
* **Что сделано:**
  * движок, созданный под скрытым слоем, стартует спящим;
  * команды `attract`, `quit`, `quiet`, `pause`, `resume` больше не будят игру — будят только команды, которым нужна видимая арена (`lobby`, `match`, `train`, `prematch` и т. д.) и показ слоя;
  * создание iframe отложено на 450 мс, чтобы логотип успел начать анимацию до длинной задачи разбора игры (0,6–1,4 с, одна задача);
  * полоса загрузки честная: последние 12% ждут `GameHost.ready` (не дольше 9 с).
* **FPS в этой песочнице не показателен.** Software-GL (swiftshader) рисует даже 2D-фон `bg` медленно: магазин даёт 30 fps против 60 без swiftshader, даже со спящим движком. Поэтому сравнение здесь по времени, а FPS нужно мерить на телефоне (dev-панель показывает fps).
* `twake.py` теперь проверяет и заставку, и поиск соперника: игра стоит, пока слой скрыт.

## Раунд 12: аудит физики и зоны удара

### Зона удара: куда ставить палец и при чём тут камера

**Что было (v3).**
* Зона задавалась в **пикселях экрана**. Поэтому её размер у мяча зависел от телефона и ракурса камеры:
  * ширина от 22 до 42 см (разброс ×1.9);
  * глубина от 25 до 64 см (×2.6).
* Зона симметрична вокруг мяча. Но по физике (замер `tzmap.py` с отключённой зоной) удар долетает, только если:
  * при свайпе вверх палец стоит на **0–170 px ниже** точки контакта;
  * при подрезке вниз — на **0–130 px выше**.
* Итог: зона пропускала только 18% ударов, которые долетели бы, и лишь 27% пропущенных ударов попадали на стол.

**Что стало (v4, `MATCH_RULES.version = 4`).**
* **Направленная зона:**
  * 150 px ниже мяча для накатов и топспинов;
  * 120 px выше — для подрезки и чопа;
  * ±48 px вбок (±36 px для мыши).
  * Свайп «не в ту сторону» отклоняется с причиной `WRONG_DIRECTION`, и совет после промаха говорит, куда ставить палец.
* **Зона в сантиметрах мира** (`zoneScale: 'world'`):
  * пиксели пересчитываются через масштаб у мяча относительно эталона 390×844 / ТВ-камера;
  * множитель ограничен 0.75–1.5, есть минимум в пикселях для пальца.
  * Итог: ширина 33–36 см на всех 12 комбинациях экрана и камеры (разброс ×1.1), глубина ×1.24.
* **Согласие зоны с физикой:** полнота 18 → **44%**, точность 27 → **42%** (`tzagree.py`).
* Оставшиеся расхождения — это тайминг: при близком пальце нужен поздний свайп, при дальнем — ранний.

**Ракурс камеры.**
* Низкая камера растягивает глубину стола на экране: те же 63 см — это 148 px на «низкой» камере и 90 px на «динамичной».
* Теперь это учитывается автоматически, и зону не нужно перенастраивать под камеру.

### Физика полёта: сверка с измерениями

Сверка с «Physics Models for Sim-to-Real Transfer in Professional-Level Robot Table Tennis» (Sony AI, arXiv:2606.28805, 2026): 58 000 участков полёта из 277 профессиональных матчей.

| Что | Было | Измерено | Сейчас |
|---|---|---|---|
| C_D медленного мяча | 0.44 | 0.55 | по таблице C_D(Re, Sp) |
| Подъёмная сила Магнуса при S≈0.3–0.6 | Cl 0.30–0.38 | 0.21–0.27 | C_M(v, ω), F = C_M ρV ω×v |
| Падение с 30.5 см (ITTF 23–26) | 23.7 см | — | 23.3 см |
| Предельная скорость падения | 8.9 м/с | ≈8.5 | 8.5 м/с |

* Модель переключается через `PH.AERO_MODEL` (`'measured'` по умолчанию, `'legacy'` — старая).
* Все решатели (ИИ, ассист, подача, прогноз) считают через одну функцию `aeroAccel`, поэтому смена модели согласована во всей игре.
* Последствия:
  * накат летит на ~30 см длиннее;
  * чоп меньше «висит»;
  * свеча выше;
  * короткие подачи ИИ стали чуть длиннее (p10 второго отскока 0.43 → 0.74 м).
* Калибровка ударов игрока: 144/144 легальных возврата.
* Карта подач ИИ: 400/400 легальных, ширина 1.0 м (порог 0.55).

**Стол — осознанно не по замерам.**
* Измеренное трение μ = 0.25, у нас 0.40. Из-за этого отскок с вращением в ~1.6 раза ярче:
  * топспин +24% вместо +16%;
  * подрезка/без вращения −25% вместо −16%.
* Это решение по ощущению игры: вращение видно с отскока (см. комментарий у `PH.MU_TABLE`).
* `physbench` печатает эталонный «ref kick» для сравнения.

### Инструменты
* `node tools/phys/physbench.cjs both` — эталонные удары на старой и измеренной модели: тест падения, предельная скорость, точка приземления, высота, запас над сеткой, отскок.

## Раунд 13 — правки по ревью (noise, UX, нейминг, звук)

## Раунд 14 — обучение указывает РЕАЛЬНУЮ зону, предсказуемые подачи, легенда шлейфа

* **Корень «учитель показывает не туда».** У замороженного мяча зона допуска считалась от скорости (=0) и схлопывалась в крошечное гало вокруг мяча, а рука-подсказка стартовала в ~170px ниже: нажатие «по картинке» отклонялось как OUTSIDE_ZONE. Теперь: (1) при скорости→0 зона плавно (непрерывно по px/с) вырастает в полный передний овал вдоль оси «мяч→рука» (in-place рамп `still`, 4×min-speed затухание); (2) обучение считает зону той же функцией, что и гейт нажатия (`game.previewPressZone()`), рисует её пунктирным овалом и ставит руку-призрак ВНУТРИ неё; (3) E2E-проверка: нажатие в показанной точке + свайп через кольцо → «Зачтено».
* **Подачи в тренировке больше не меняются внезапно.** Сложность шара нарастает ровно вместе со снятием костылей: freeze = идеально прямой, approach = ±0.10 drift, ring = ±0.20, без подсказки = прежний полный коридор; глубина/высота подачи теперь одинаковые у всех шаров шага (раньше второй шар уже получал полный случайный коридор с новой дугой). Финальный шаг «Закрепление» смягчён до разумного экзамена (5.9 м/с вместо 6.4, спины умеренные).
* **Цвет шлейфа документирован** прямо на интро-экране обучения: оранжевый = верхнее вращение, синий = нижнее, зелёный = боковое, серый = почти без вращения (яркость ∝ силе вращения, толщина ∝ скорости мяча).

Тесты: 178/1 (без изменений). press-zone.test.js: устаревшее «круг при нулевой скорости» заменено на документированный контракт «замороженный мяч → обучаемый овал» (22/22).

## Раунд 15 — кольца честные и стабильные, зоны шире, dev-панель убрана

## Раунд 16 — шлейф = вердикт точности, «зелёный удар ≈ гол»

* **Шлейф теперь оценивает ВВОД игрока, а не тип вращения** (тип вращения остался на шлейфе соперника). Оценка в `Game.hitInputGrade()`:
  * место = расстояние точки нажатия от идеальной точки встречи (px),
  * тайминг = насколько пик скорости свайпа совпал с моментом контакта (сек),
  * **зелёный** (≤22 px и ≤50 мс — редко даже у человека; задумано), **жёлтый** (≤44 px и ≤120 мс), иначе **красный**.
* **Зелёный удар оплачивается очком:** ~88% идеальных ударов помечаются `golden='win'` — бот «не читает» мяч, теряет позицию и не замахивается вовсе (гейт в `OpponentAI.think`). Остальные 12% бот тащит чудом — чтобы матч не выглядел запрограммированным.
* **«ИДЕАЛЬНО!»** всплывает над столом при зелёном ударе.
* Легенда на интро обучения обновлена: «идеально · почти очко / на грани / мимо зоны или тайминга».

Тесты движка: 178/1. E2E-проба (tgold): реальный контакт → вердикт назначается; `golden='win'` → бот не отбивает, без флага — отбивает.

## Раунд 17 — экспертный UI/UX-аудит + приведение к спецификации TMA
**Каркас (TMA spec):** убрана нарисованная рамка телефона (#device radius 52 + кольца) — приложение full-bleed; на широких экранах — узкая центральная колонка без bezel. Safe-area Telegram теперь считается суммами (safeAreaInset + contentSafeAreaInset) сверху (--tgt) и снизу (--tgb), обновляется по событиям contentSafeAreaChanged/safeAreaChanged/fullscreenChanged/viewportChanged; внутри TG env() выключается от дублирования. Fullscreen запрашивается жестом «В бой» (Bot API 8.0: requestFullscreen в user gesture), ориентация лочится только в портрете и на мобильных, unlock/exit — защищённые. Во время матча/обучения — enableClosingConfirmation (защита от случайного закрытия), по выходу — снятие. `color-scheme: dark` в meta.

**Функциональные баги (найдены пробами, исправлены):** режим «С другом» запускал бота — удалён; задание за 8 гемов фармилось бесконечно — клейм сохраняется в S.questDone; locked-сундук был тупиком — тап запускает открытие (очередь — по-доброму отказ с тоюстом), статичная «3ч» заменена на живой таймер; подарок не воскресал — настоящий кулдаун S.freeAt, живой авто-таймер и ре-арм кнопки; экран результата терял рейтинг/опыт при раннем выходе — награды применяются мгновенно и идемпотентно; после Level-Up уровень не повышался в состоянии; пауза → настройки молча запускали розыгрыш — resume только когда закрыты ВСЕ листы (match и train); бадж «Пропуска» был зашитой цифрой 2 и воскресал после перезагрузки — считается из состояния, обновляется после клеймов; слот «След мяча» в профиле показывал чужую накладку — добавлен реестр BONUS_ITEMS (t-coral), стартовые предметы отмечены как owned; покупка премиума дублировала обработчики (innerHTML-re-mount) — теперь честный Router.go(replace); mm-таймер «0:60+» — формат m:ss; подсказка «Твоя подача» могла висеть при подаче бота — жёсткий гейт по server>0 + скрытие на point; таймер магазина уходил в минус — суточный цикл; карточка легендарного следа в сундуке рисовала undefined-звезду — заменена на ItemArt.comet.

**Рейтинг без выдумки:** экран «Рейтинг» показывал придуманные места («1 284», «▲38», «топ 4%») из локального списка.

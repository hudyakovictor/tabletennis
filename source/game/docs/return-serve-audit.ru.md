# Проверяемый аудит приёма и подачи — 2026-10-27

Это не перечень предположений и не число ручных партий. Аудит закреплён
детерминированным тестом `tests/return-serve-audit.test.js`: один запуск
выполняет **ровно 300 сценариев**, считает их в самом тесте и завершится
ошибкой, если число изменится или хотя бы одна проверка не пройдёт.

```sh
cd source/game
npm run test:audit
npm run coverage:return-serve
npm run test:browser
```

`coverage:return-serve` использует `c8`/V8; `tests/helpers.cjs` компилирует
каждый игровой исходник под его настоящим именем, поэтому отчёт не выдаёт
склеенный `eval` за покрытие исходников. Отчёты пишутся в игнорируемый
`test-results/coverage-return-serve/`.

## Подтверждённые исправления

1. **Путь допуска вместо необратимого `pointerdown`.** Стартовое решение
   сохраняется для отчёта, но `notePressProgress()` может допустить только
   реальный путь владеющего указателя в актуальную зону. Первый фактический
   вход фиксируется один раз: последующие samples внутри не перезаписывают
   `entryZone` и не превращают продолжение правильного удара в
   `WRONG_DIRECTION`. Сам `WRONG_DIRECTION` остаётся окончательным запретом
   контакта, не уничтожая доказательство старта.
2. **Честная кинематика ввода.** Коалесцированные samples имеют собственные
   DOM timestamps, полный путь не урезается хвостом из 64 samples, а
   zero-duration сегменты не получают epsilon-скорость.
3. **Один владелец жеста и согласованные координаты.** Чужие pointer events
   не меняют активный штрих; raw координата используется для жеста, а
   clamped — только для безопасного наведения ракетки. Оси нормализованы по
   короткой стороне canvas.
4. **Единая локальная геометрия ракетки.** Endpoint, grace/подсказка,
   непрерывный sweep и оценка качества контакта используют диск в плоскости
   `pad.normal` и нормальную глубину; старые вызовы только с центром ракетки
   сохраняют совместимый XY/Z fallback.
5. **Подача.** Падающий подброс использует swept sphere, а граница законной
   высоты включает ровно `serveTossMinRise` в пределах численной погрешности.
6. **Физика и прогноз.** Интегратор позиции применяет стадии RK4 при
   velocity-dependent drag/Magnus; сфера удара нормализует normal;
   окончательные проверки полёта и прогноз ракетки используют `PH.SIM_DT`,
   а не грубый шаг поиска.

## Факты запуска и ограничения

- Полный Node-набор на момент аудита: **244 / 244 pass**.
- V8/c8-coverage на том же наборе: **60,20%** релевантных исполнимых строк;
  это измерение, а не оценка по количеству тестов.
- `npm run test:browser`: **185 / 185 checks pass** на desktop и
  эмулируемом touch; `npm run test:diagnostics`: **20 / 20**, а
  `npm run test:missshots`: **8 / 8**. Browser-набор проверяет реальные
  Pointer Events и собранный standalone HTML; это необходимо потому, что
  Node fixtures не исполняют DOM capture, coalescing и Canvas/WebGL.
- Автоматизация не доказывает поведение на каждом физическом телефоне,
  нестабильные browser timestamp-особенности или субъективное ощущение
  удара. Она также не доказывает отсутствие всех будущих дефектов. Для
  отдельного реального промаха нужен экспорт диагностического JSON/JSONL,
  а не перенос причины из этой матрицы наугад.

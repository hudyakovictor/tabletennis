# TOPSPIN ARENA

Самодостаточная WebGL-игра в настольный теннис. Исходники — `tt/src/`, готовые страницы — `table-tennis-topspin.html` и `play/index.html`.

## Запуск

Откройте `play/index.html` в браузере с WebGL или запустите статический сервер:

```sh
python3 -m http.server 8000 --bind 0.0.0.0 --directory play
```

Игра не требует загрузки внешних ресурсов. Сохранения привязаны к адресу страницы/браузеру.

## Управление камерой и интерфейс

- Колесо мыши: приблизить/отдалить стол.
- Зажатая правая кнопка + движение вверх/вниз: поднять/опустить камеру. Масштаб при этом не меняется; боковые движения игнорируются.
- **F** или кнопка разворачивания справа: полный экран на десктопе (если разрешён браузером).
- Три неподвижных фронтальных вида: «Игра», «Обзор», «Ближе». Основной наклон вниз одинаковый на всех экранах — 25°: видны обе половины стола. Под пропорции экрана подстраивается только кадрирование. Ручная высота ограничена безопасными углами 18–42°.
- **C**: сбросить вид, высоту и масштаб; **1–3**: выбрать пресет. Все три вида доступны в настройках. Ползунков камеры нет; на телефоне свайпы не меняют высоту или масштаб. При переходе с мыши на касание ручные поправки сбрасываются.
- Кадр учитывает не только стол с ножками, но и ракетку соперника в верхней точке замаха и подброс. Над игровым объёмом остаётся минимум 10% экрана; прежняя пропорция 1:3 больше не обрезает ракетку ради нижнего отступа. Игровые надписи находятся в нижней области, счёт — вверху слева.
- Шлейф мяча: непрозрачность 20%.
- Во время розыгрыша короткий клик или тап — простой удар; свайп позволяет задать направление и вращение. Удержание без движения не бьёт, каждый жест расходуется только на один контакт. На подаче сначала нажмите для подброса, затем выполните свайп.
- Инструкций про подачу в обычной игре нет. Снизу — разбор последней попытки на 7 секунд: крупное название удара и результат, ниже — основное вращение в об/с. Скорость и все компоненты вращения доступны только в разборе на паузе. Название жеста само по себе не означает успешный удар.
- Помощь в наведении на входящий мяч работает только при свежем ударном жесте. Демо запускается отдельно из меню; выход из него очищает искусственные жесты, а первое игровое нажатие переводит в ручное управление.

## Ракетки без модели руки

- Удалены меши кисти, большого пальца, предплечья и рукава у обеих ракеток.
- Угол ракетки задаётся текущим жестом и плавным наклоном при перемещении. Предыдущий угол не используется как база нового поворота: вращение не накапливается, в покое ракетка стабильна.
- Отрисовка не изменяет игровую ориентацию. Основание, накладки и ручка используют один quaternion; красная и чёрная стороны закреплены за поверхностями, а не переключаются от скорости мяча.
- Удалён конфликтующий модуль `85_bioRacket.js`. Исправлены блокировавшие запуск синтаксические ошибки и браузерный `require`, инициализация позы ИИ, двойное применение его удара и ошибки игровых уведомлений.
- Регрессионные проверки: `tests/paddle.test.js`, разбор автономной сборки, стабильность при 30/60/120 FPS и повторной отрисовке в Chromium на десктопе и мобильном экране.

### Хват, контакт и проводка

В настройках выбираются **Shakehand / Penhold** и **правша / левша**; выбор сохраняется. Нейтральный наклон — 15° и 5° соответственно, у Penhold рукоятка направлена вверх. Локальный поворот и проводка зеркалятся относительно Shakehand: переворот рукояткой вверх не должен разворачивать боковой наклон кисти в противоположную сторону.

Общие профили и контроллер фаз — `38_paddle_motion.js`. Финальная физическая нормаль удерживается в кадре контакта, затем ракетка выполняет отдельную проводку удара и плавно восстанавливается. У подрезки плоскость открывается, у топспина закрывается. Ограничения контакта учитывают высоту и силу жеста; при высокой помощи решатель может независимо уточнять наклон кисти и траекторию замаха, не подменяя физику мяча.

Добавлены кратчайшие угловые переходы, гистерезис FH/BH, прогноз примерно 30 Гц независимо от FPS, геометрический зазор над столом и запись поворота рукоятки в replay v2 без увеличения размера кадра. [Аудит по 16 факторам и ограничения оценки](docs/paddle-audit.ru.md).

### Единая помощь и понятные маркеры

Ползунки области попадания и автодоводки удалены. `12_match_rules.js` задаёт общие допуски и помощь; старые индивидуальные значения не загружаются и не сохраняются. Хват, ведущая рука, камера и звук остаются личными предпочтениями. Карьерные perks, менявшие индивидуальную помощь или обходившие сетку, выведены из игры; остальные механики прогрессии сохранены.

Мяч отбивается **ракеткой**. Дополнительные точки и прицелы удалены; системный курсор скрыт над полем во время игры и возвращается в меню, диалогах и на паузе. Скобки **у мяча** — время/пространственная доступность удара: пунктир при приближении, сплошные при открытом окне. На ракетке в готовности кольца больше нет; физическая деревянная кромка остаётся частью модели. Нужен свежий жест: метка сама мяч не отбивает. [100 пунктов анализа, точные значения и границы обещания](docs/control-indicators-100.ru.md).

## Диагностика пропуска и снимок

- **Автоснимки:** в `play/index.html` первый тап/клик каждой попытки удара снимается без паузы и без включения записи. Откройте **«Настройки» → «Калибровка» → «История промахов»** и нажмите на снимок, чтобы посмотреть или скачать JPEG. Успешный контакт удаляет соответствующий кадр; остаются до 40 последних попыток без контакта.
- Область по умолчанию — **±350 CSS px** от нажатия (можно выбрать ±300 или ±400; у края она обрезается экраном). Новые снимки сохраняются в разрешении игрового рендера, которое зависит от качества графики. Старые маленькие кадры останутся в галерее, но их разрешение повысить нельзя. Красный маркер — нажатие; зелёный контур — допуск, центр которого может быть прогнозируемой точкой встречи, а не текущим положением мяча.
- Галерея хранится на этом устройстве и доступна в оболочке, но не в отдельном HTML движка. При запрете/нехватке хранилища выводится предупреждение: текущие кадры доступны до закрытия страницы, после перезагрузки могут пропасть. Они не отправляются автоматически. Проверка: `cd source/game && npm run test:missshots`.
- В обычной сборке `play/index.html`: **пауза → «Диагностика» → «Включить запись» → «Продолжить»**. Повторите промах, затем снова откройте диагностику и нажмите **«Подготовить отчёт JSON» → «Скачать отчёт»**. В обучении есть отдельная кнопка «Диагностика».
- Снимок в оболочке: **пауза → «Скриншот» → «Скачать PNG»**. При включённой записи кнопка **«Кадр»** во время игры запоминает момент; если он есть, показывается именно он (с указанием времени), иначе — текущая сцена. «Сделать новый скриншот» заменяет отмеченный кадр. Если скачивание в браузере или Telegram запрещено, попробуйте удерживать изображение или поделиться им. PNG содержит WebGL-сцену и 2D-слой игры, **но не счёт и кнопки оболочки**. Готового PNG в репозитории нет: файл создаётся при скачивании. Это не исправляет системное сохранение скриншотов устройства.
- В автономной версии `source/game/play/index.html` аналогичные действия находятся в паузе: **«Подробная запись»**, **«Подготовить отчёт JSON»**, «Кадр» и **«Скриншот» → «Скачать PNG»**. Кнопка старого JSONL-журнала остаётся отдельно.
- Подробный отчёт включает условия при нажатии и отпускании, текущие/прогнозируемые координаты мяча, входной гейт, таймеры и slow-mo, данные подшагов контакта, отмены указателя/потерю фокуса, ошибки, сборку, настройки, устройство и WebGL. `anomaly` обозначает наблюдение, а не доказанную причину ошибки. В памяти хранятся до 30 секунд игрового счётчика и 16 000 событий; фактическая продолжительность отображается на паузе. Локальный IndexedDB-резерв ограничен 64 порциями по максимум 256 событий (порции могут быть меньше) и одним последним отмеченным кадром; старое перезаписывается, незаписанная порция может пропасть при сбое. При доступном хранилище отчёт и отмеченный кадр можно восстановить после остановки записи и перезагрузки той же вкладки. При недоступном хранилище отчёт из памяти по-прежнему работает, восстановление после перезагрузки — нет.
- Данные не отправляются автоматически. Отчёт содержит координаты касаний и сведения об устройстве: проверьте его перед отправкой. Для удаления локального резерва очистите данные сайта в браузере. Проверка: `cd source/game && npm run test:diagnostics` (Chromium, включая мобильную эмуляцию; физический телефон не проверяется).

В управляемой симуляции найден один воспроизводимый пропуск: при зелёном мяче и неподвижном нажатии около 300 мс быстрый мяч может пройти ракетку до отпускания, когда тап распознаётся. Это не доказывает, что тот же механизм вызвал любой конкретный промах; подробный журнал нужен для проверки реального случая.

## Калибровка зоны нажатия

**Пауза → «Зона нажатия»** показывает овал у мяча: область начала нажатия мыши/касания. Это **экранный допуск ввода**, не размер ракетки и не качество контакта. Контракт — `MATCH_RULES` версии 4 в `tt/src/12_match_rules.js`; переключатель `zoneShape: 'oval' | 'circle'`.

- Длинная ось овала направлена по **экранной** скорости мяча (разность двух проекций `project(ball)` и `project(ball + vel·dt)`, перспектива учтена). Передняя полуось — `min(|v|·ovalLeadSec + ovalForwardPx, ovalForwardMaxPx)`. Между `ovalMinSpeedPx` и `ovalFullSpeedPx` круг и овал смешиваются smoothstep-ом, а ось плавно поворачивается от направления «мяч → ракетка» к экранной скорости. Для неподвижного мяча `along > 0` означает сторону ракетки/игрока.
- Старый круг `pressHitZone` оставлен только для A/B-сравнения. **Все числа ниже генерируются из `MATCH_RULES` командой `npm run docs:rules`; вручную их не редактируют.**
- При `pointerdown` в журнал сохраняется **стартовое свидетельство** (`score`, `along`, `across`, тип ввода и код причины). Допуск контакта — это путь активного указателя: старт внутри допускает жест сразу; старт снаружи становится допустимым только если тот же владеющий жестом указатель реально войдёт в актуальную живую зону на move/up. Одно лишь движение мяча, помощь позиции/траектории, наведение ракетки или CCD не могут создать такой вход.
- Допуск зоны всё ещё не является ударом: короткий клик/тап или свежий свайп срабатывают только у ракетки после разрешённого отскока. Для свайпа также проверяется направление; `WRONG_DIRECTION` окончательно закрывает контакт, но не затирает стартовое свидетельство в журнале. Один жест расходуется на один контакт. Коалесцированные DOM-события хранят собственные timestamps: сегмент с нулевой длительностью сохраняет геометрию для диагностики, но не получает выдуманную скорость.
- Своя подача во время падающего подброса проверяется отдельной зоной по оси падения (`pressServeZoneOval`): мяч должен уже падать после подъёма от точки выпуска не ниже `serveTossMinRise` (граница включительна с численной погрешностью `1e-6`). Экранная зона и физические допуски ракетки — отдельные слои.

Отладка ввода:

- Кольцевой JSONL-лог последних 30 секунд всегда включён в игре. **Пауза → «Сохранить последние 30 с»** скачивает `topspin-input-log.jsonl`: версии, кадр/FPS, pointer-события, мяч и ракетка в мире и на экране, решение гейта, исход и коды отказов (`OUTSIDE_ZONE`, `WRONG_DIRECTION`, `STATIC_CLICK` и др.). Анализ с CSV, PNG-теплокартой отклонённых нажатий и рекомендацией по 90-му перцентилю: `npm run analyze:log -- путь/к/логу.jsonl`.
- **«Калибровка попадания»** в паузе показывает по подаче и приёму число нажатий/отказов/ударов и перцентили `along/across`.
- Отдельный пункт меню **«Калибровка зоны»** ведёт по заданиям: углы стола, неподвижный мяч, медленный и быстрый мяч, своя подача, сила и спин — сначала мышью, затем касанием. Каждый шаг заканчивается числом и рекомендацией; данные скачиваются файлом для разработки. Персонального профиля зоны нет намеренно: в PvP он давал бы игрокам разный допуск ввода и превращал калибровку в покупку хитбокса.

## Звук небольшого клуба

Победу отмечают отдельные неритмичные хлопки шести зрителей, обычное выигранное очко — короткая реакция двоих. Нет непрерывного стадионного гула. На 4-м, 8-м и последующих кратных четырём ударах возможна тихая синтезированная вокальная реакция 2–3 наблюдателей; пауза между реакциями не меньше 3,2 секунды. Короткий комнатный ревербератор оставляет удары по мячу на переднем плане. Выключение звука и выход в меню обрывают запланированные реакции.

## Обучение и устройство ввода

Инструкции выбираются по возможностям указателя, не по ширине окна: узкое окно десктопа остаётся мышью. На гибридном устройстве фактическое касание/нажатие мыши сразу меняет подсказки. Для сенсорного ввода — короткие инструкции про свайп, для мыши — ЛКМ и направление. В обучении нет нижней панели и зацикленных анимаций свайпа. Сверху — цель, номер упражнения и прогресс; эта область не перехватывает ввод. Следующее упражнение включается автоматически после успешных попыток. Инструкция по жесту, пропуск упражнения и выход доступны только на паузе.

Логотип с настоящим альфа-каналом: `tt/assets/table-tennis-ultimate.png`. Он получен из нижнего левого варианта предоставленного пользователем изображения и встроен в сплеш/меню обеих автономных HTML-сборок.

## Разработка и проверки

Требуются Node.js 22+, npm, Python 3. Chromium для браузерных тестов поставляется npm-пакетом; отдельно скачивать браузер не нужно. На Linux тестовый скрипт также распаковывает комплектные библиотеки NSS во временный каталог. Можно задать `CHROME_BIN` для своего Chromium.

```sh
npm ci
npm run build          # обновляет ОБЕ готовые страницы в репозитории
npm test               # логика, сохранения, WebSocket relay, актуальность сборок
npm run test:audit     # 300 детерминированных сценариев приёма/подачи
npm run coverage:return-serve # V8/c8 line coverage релевантного игрового контура
npm run test:browser   # настоящий Chromium/WebGL: desktop + portrait viewport, fullscreen, полный розыгрыш без ввода и рендер звука через OfflineAudioContext
```

Для отдельной сборки в заданный файл: `python3 tt/build.py /путь/к/game.html`.

Старые исследовательские скрипты в `tt/tools/` сохранены, но многие используют абсолютные пути из прежнего окружения. Воспроизводимый регрессионный набор — `tests/`, он запускается также в GitHub Actions.

## Сетевой сервер — экспериментально

```sh
npm run relay -- 3001
```

Адрес relay задаётся через параметр страницы `?net=wss://ваш-сервер`. Для HTTPS-страницы нужен WSS; нельзя указывать `localhost` для подключения из чужого браузера. Сервер слушает `0.0.0.0`, порт также можно задать переменной `PORT`.

**Онлайн-геймплей ещё не завершён.** Тесты relay подтверждают маршрутизацию сообщений и жизненный цикл комнат, но НЕ полноценный двухсторонний матч. Сейчас гостевые удары не передаются в авторитетную симуляцию, а локальные игровые автоматы обоих клиентов могут расходиться. Не следует использовать этот режим как готовое PvP.

Подробности исправлений и границы проверки: [аудит приёма и подачи](docs/return-serve-audit.ru.md) и [аудит ракетки](docs/paddle-audit.ru.md).

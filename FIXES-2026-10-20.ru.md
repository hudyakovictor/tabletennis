# Исправления управления TOPSPIN ARENA — 2026-10-20

## Как проверить сборку

1. Распаковать архив **в новую папку**, сохранив исходный проект отдельно.
2. Открыть `play/index.html` в браузере с WebGL. Для публикации заменить содержимое каталога `play/` на хостинге.
3. При ограничениях открытия локальных файлов: `python3 -m http.server 8000 --directory play`, затем открыть `http://localhost:8000` на том же компьютере.
4. Для проверки с телефона сервер должен быть доступен телефону по сетевому адресу компьютера; `localhost` на телефоне означает сам телефон.

Для игры установка npm-зависимостей не требуется. Обе HTML-страницы автономны, звук и логотип встроены.

## Управление

- **Десктоп:** курсор наводит ракетку; удерживать ЛКМ и провести мышью для удара. Клик без движения не бьёт.
- **Телефон:** нажать и провести пальцем. Второй палец отменяет текущий жест.
- **Подача:** нажать на игровое поле и сделать свайп. Подброс запускается первым нажатием, жест может завершиться до вершины; контакт выполняется только при законном падении мяча.
- Можно отдельно нажать/отпустить для подброса, затем начать новый свайп в зоне уже летящего мяча. Начало нового свайпа на подъёме теперь не блокирует его навсегда.
- Подброс, запрошенный во время возврата ракетки в центр, запускается после возврата, даже если короткое нажатие уже отпущено. Пауза или сброс отменяют этот запрос.

## Причины и изменения

| Ошибка | Причина | Исправление |
| --- | --- | --- |
| Свайп при подаче не срабатывает | `pointerdown` проверял фазу подъёма/падения и сохранял отказ на весь жест | Пространственный допуск вычисляется при нажатии; законность фазы — при физическом контакте |
| Первый жест зависит от старой позиции мяча | В `SERVE_READY` зона считалась до переноса мяча в точку подброса | Первое нажатие на игровом поле трактуется как команда подброса; требование реального свайпа сохраняется |
| Быстрый тап проглатывается | Очередь подброса требовала всё ещё удерживать указатель после возврата ракетки | Запрос сохраняется после отпускания, но очищается паузой/сбросом |
| Ракетка самопроизвольно перемещается после отпускания | Глубина стойки менялась с начальной Y жеста на конечную Y | Отпускание сохраняет стойку. Новое нажатие или новое наведение мышью задают следующую |
| Ракетка меняет цель при работе с меню | Глобальный hover обновлял указатель за паузой и интерфейсом | Ввод ограничен игровым контекстом; движение по интерфейсу не переназначает цель |
| Посторонний указатель вмешивается в свайп | События `pointermove` не проверялись по владельцу жеста | Один `pointerId` владеет жестом; мультитач отменяет его до отпускания всех пальцев |
| Быстрый свайп теряет начало | Coalescing записывал первую `pointermove` поверх `pointerdown` в одном кадре | Начальная точка неизменна; объединённые метрики пересчитываются, время начала движения не теряется |
| Отладочная область не совпадает с вводом | Отладка не учитывала те же множители зоны/подачи | `Game.measurePressZone` используется и вводом, и отладкой. В готовности показывается команда подброса, а не ложный овал |
| Свежий приём рядом с ракеткой отвергается | Перевёрнут знак `r·v`: сближение и удаление перепутаны | Резервный контакт проверяется у ближайшего прохождения/на удалении; физический CCD сохранён |
| Состояние старого указателя переживает начало очка | Сброс ракетки чистил SwipeTracker, но не карту указателей | Сброс использует общий `cancelInput` |

Изменены `12_match_rules.js`, `40_swipe.js`, `70_game.js`, `80_ui.js`. Физический решатель отскока, коэффициенты вращения, размеры базового захвата и существующие множители помощи не увеличивались. Глобальная замена физики не производилась.

## Проверки

Команды из корня проекта, после `npm ci`:

```sh
npm run build
npm test
npm run test:browser
npm run test:input
```

- Исходная версия проходила старые 174 логических и 169 браузерных проверок. Они не обнаруживали перечисленные последовательности реального ввода.
- Новый исходный воспроизводящий набор: 21/39 успешных проверок, 18 отказов на трёх размерах экрана. Сохранён как `test-results/evidence/input-before.json`. Это отдельный исходный набор, не все позднее добавленные сценарии.
- Финальный логический набор: **179/179**. Браузерный ввод: **63/63**. Общий изолированный WebGL-набор: **169/169**, без необработанных исключений.
- Браузерные наборы следует запускать последовательно: игра реагирует на `focus/blur`. Один параллельный прогон завершился тайм-аутом ожидания RAF; его лог сохранён отдельно, а общий WebGL-набор повторно запускался изолированно.
- Финальные итоги и логи находятся в `test-results/evidence/`.
- Новый набор покрывает 1280×760 (мышь), 390×844 (сенсорный портрет), 844×390 (сенсорный ландшафт); сценарии подачи выполняются с шагом 30/60/120/144 FPS.
- DOM-сценарии вызывают настоящие обработчики событий и полный `Game.update`, а не `tryPlayerHit` напрямую. Для синтетических ID отключён только `setPointerCapture`. Отдельные сценарии используют браузерный mouse/touch-ввод с настоящим захватом указателя и проверкой попадания в DOM.
- Приём проверен на управляемой входящей траектории после своего отскока; правила аута/сетки/двойного контакта, демоматчи и жизненный цикл покрываются также прежними регрессиями.
- FPS в детерминированных сценариях — шаг симуляции, а не замер производительности на реальном устройстве.

## Ограничения

Это исправление подтверждённых дефектов ввода и момента контакта, не обещание отсутствия всех багов игры. Баланс, сложность и субъективное ощущение управления требуют игровых сессий с людьми. Проверки выполнялись в headless Chromium/WebGL со SwiftShader: реальные iPhone/Android, Safari и Telegram-клиенты отдельно не тестировались.

Существующий экспериментальный онлайн-режим не доработан до полноценного авторитетного PvP; в этой поставке это не исправлялось. Прежние исторические аудиты в `docs/` могут описывать старое поведение; для изменённого контракта подачи актуальны этот отчёт и README.
